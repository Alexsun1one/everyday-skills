# Reference-Informed Builds / 参考事实搭建

When the subject has real-world structural facts: a named architecture pattern, apparatus, plant layout, protocol stack, historical machine, or brand ops floor that is easy to get wrong.

References are for **truth and recognition**, not for copying a LEGO® set or another artist's layout.

## When To Gather References

- user names a specific system, protocol, machine, plant, or pattern
- wrong part count or wrong layer order would mislead
- audience expects recognizability

Skip when the subject is generic/symbolic.

## What To Extract

```text
what it is:
must-have modules/parts:
connection order:
stable structural cues:
common confusions:
source notes:
uncertainty:
```

Translate into brick world: module blocks, foundation slabs, roads, gates, gears — **original** builds only.

Do not: reproduce official sets, logos, licensed themes, or trace source photos.

## Prompt Block

```text
Reference-informed cues: [subject] should include [must-have modules/order]. Translate into original interlocking studded bricks with authentic stud geometry, ABS sheen, and connection-as-relation. Do not copy official LEGO sets, logos, or licensed characters. Do not add unsupported parts.
```

## User Asks For A Trademarked Set

1. Identify the *structure job* the set was doing.
2. Build an original equivalent with different silhouette/colors.
3. Say so: "搭了原创等价物，未复刻官方套装。"

## QA

Accept if recognizable, key parts correct, uncertainty not hidden as fact, connection still carries meaning, no trademark drift.
Reject if mechanism wrong, brand confused, reference detail overwhelms the structure argument, or a real set/logo appears.
