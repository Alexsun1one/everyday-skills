# Failure Patterns / 失败模式库

Name the failure. Then repair, regenerate, or reroute. Do not call a charming brick pile "mostly fine."

## Common Failures

### Decorative Bricks
Symptom: removing the bricks changes nothing; meaning lives in arrows/labels only.
Fix: make physical placement *be* the relation (stack, row, wall, gear, seesaw).

### Brick-Textured PPT
Symptom: flat boxes/arrows with ABS grain.
Fix: real 3D assembly with studs, clutch, depth; remove giant arrows.

### Atmosphere Instead Of Structure
Symptom: pretty cityscape, no focal module, no connection grammar.
Fix: name the relationship; one focal build; run Build Test.

### Fake Data Beauty
Symptom: stacks/flags imply numbers that are wrong.
Fix: reject; use `data-status-builds.md` exact data block or native chart.

### Trademark Drift
Symptom: real LEGO set, LEGO logo/wordmark, licensed minifig, real-person likeness.
Fix: original equivalent; strip logo; recast minifig.

### Text Overload / Floating Text
Symptom: title+paragraph+12 labels; or captions not on carriers.
Fix: `text-strategy.md` + `lettering-and-text.md`; move title outside.

### Template Lock
Symptom: every topic is the same gray-blue service town.
Fix: creative divergence + Swap Test; content-specific tiles.

### Wrong Owner
Symptom: bricks forced onto cooperation-cast, single paper action, strict chart, full social card.
Fix: reroute to busy-town / paper-operators / chart / card skill.

### Voxel / Minecraft Drift
Symptom: cubes without studs/tubes, blocky Minecraft look.
Fix: regenerate with HARD NEGATIVES; authentic stud geometry.

### Instruction Without Assembly Order
Symptom: "instruction mode" but no numbered steps / parts call-out.
Fix: restore booklet cues; order must be readable.

### Exploded Without Connection Lines
Symptom: floating parts with no assembly axis.
Fix: thin connection lines; parts in assembly order.

## QA Rule

Name → Repair / Regenerate / Reroute. Charming-but-unclear = failed.
