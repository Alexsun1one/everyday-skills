# Series and Chaining / 串联

Use this when the idea needs more than one image. Readers feel quality when the set reads as **one build** — one town, one baseplate world, one brick palette, one minifig — not as N unrelated photos. In LEGO terms chaining is literal: **the town gets built up across the set**, or **the instruction booklet steps forward**. Two scales of chaining work at once: continuity across images (inter-image) and a readable build-order within each image (intra-image).

## Two Kinds of Chaining

### Intra-image chaining / 图内串联
One reader path threads anchor → action → result inside a single image. A baseplate **road or conveyor** runs from the source module, through the focal action (a minifig building/inspecting/gating), to the outcome module. Step numbers or road signs mark each stop; the minifig is *on* the route, not beside it.

Accept: one blue road/conveyor with 2–4 labeled stops; the minifig touches the build at the focal point; start/change/result visible in one scene.
Reject: equal-weight modules with no route; a minifig standing beside a pretty town; labels scattered with no route logic.

### Inter-image chaining / 图间串联
The set shares a baseplate world, brick palette, minifig identity, label style, and a **progressing build state**. Image 2 advances the same build — "same town, next thing built" — not "new set."

Accept: same district world, same minifig(s), same palette and label tiles, same camera; the build state progresses image to image.
Reject: image 3 looks like a different product line; each image repeats the same scene; the set could be reordered without losing meaning.

## Continuity Dimensions

Plan what STAYS constant vs what CHANGES per image.

**Stays constant / 保持不变:** the **baseplate world / district** (service town, factory floor, knowledge town, cozy street — don't switch mid-set); the **brick palette** and what each color means; the **minifig identity** (same role-fig(s), same accessories); the **label container** style (printed tiles, or signboards, or step badges — pick one); the **camera & light** (finished studio, or instruction vector — don't mix); the **road/conveyor language** (same width, same blue = live).

**Changes per image / 每张变化:** the specific **relation** from `connection-grammar.md`; the **focal module / district** in play; the **minifig action** (a new build verb); the **build state** (empty studs → half-built → tiled-done; gray → finished colors); the **labels** (new short labels per relation; a recurring motif label may return).

## Series Roles

Assign each image a role: opening → build → turn → resolution.

| Role | 角色 | Job |
|------|------|-----|
| Opening / 开场 | Frame the question or the empty site | A bare baseplate, scattered loose bricks, an unbuilt plan, the problem |
| Build / 展开 | Show the mechanism going up | A minifig assembling modules, routing roads, snapping connections |
| Turn / 转折 | Tension or contrast | A gate/inspection, a cracked module, an A/B fork, a tradeoff seesaw |
| Resolution / 收束 | The payoff | The finished town/build, tiled-clean modules, the lit route complete |

**Recommended patterns:**

| Length | Pattern | Example rhythm |
|--------|---------|----------------|
| 2 | Opening → Resolution | 空底板 → 建成; 散件 → 成品 |
| 3 | Opening → Build/Turn → Resolution | 规划 → 搭建 → 落成 |
| 4 | Opening → Build → Turn → Resolution | 散件 → 搭主体 → 质检/分叉 → 交付 |
| 6 | Opening → Build A → Build B → Turn A → Turn B → Resolution | 空地 → 地基 → 连路 → 关卡 → 校验 → 落成 |

When the topic allows, include at least one **non-engineering** build (a knowledge town, a life routine, a research map) so the set doesn't look like it only draws software.

## The Throughline Build / 主体串联

One continuous build runs across the whole set: image N ends where image N+1 begins. The town/build grows; the road extends; the modules go from bare studs to tiled-done. The growing build *is* the argument made physical.

**Handoff rules:** the end state of image N = the start state of image N+1 (which modules are built, where the road reaches, the minifig's posture). State the handoff in the series plan. The build and the minifig progress together; don't reset to an empty baseplate unless the topic explicitly restarts.

**State progression axis** — pick one and advance each image:

| Axis | Start | End |
|------|-------|-----|
| Construction | bare baseplate, loose bricks | finished, tiled-clean build |
| Route | road reaches station 1 | road reaches the final station |
| Verification | unstamped modules | stamped / mint-green / passed |
| Scope | one module | the full district/town |

Labels reflect the current state (e.g. 地基 → 主体 → 校验 → 落成).

## Instruction-Booklet Chaining / 说明书串联

A special, very LEGO-native series: the whole set **is one instruction booklet**. Each image is one or two steps. Image 1 = steps 1–2, image 2 = steps 3–4, etc., each showing the build as it looks after those steps with the new parts highlighted and a parts call-out box. A small finished-preview thumbnail recurs in the corner of every image. This is ideal for a how-to, a setup guide, a recipe, or a prompt assembled part by part.

## Motif & Callback / 原元素串联

A recurring small element returns across the set and pays off at the end — pick one prop from `primitives.md` (a flag, a stamp tile, a specific colored module, a light brick, a key minifig). Introduce it early (e.g. an un-stamped tile, a bare slot, a dim light brick), transform it mid-set, and return it transformed in the resolution (the stamp lands, the slot is filled, the light brick glows). Keep the same brick material and label style; change only the state.

**Per-image relation vs set motif:** the relation comes from `connection-grammar.md` (what one image explains); the motif is the recurring element tying the set together. One image = one relation; the whole set = one motif arc and one growing build.

## Series Planning Template

```text
topic throughline:
set length:
shared world / district / palette / minifig / label style:
mode (consistent, or booklet):
per image:
  - role (opening / build / turn / resolution):
  - anchor:
  - relation (from connection-grammar):
  - minifig + action:
  - scene / elements:
  - build state (on the progression axis):
  - labels:
continuity checklist:
```

Checklist: same district world; same minifig identity; same label container; same camera & light; the build state progresses (image N end = image N+1 start); the motif is introduced and pays off; no redundant images; at least one non-engineering build when the topic allows.

## Avoid

- The same scene repeated with only label swaps.
- Disconnected worlds/palettes between images.
- A set that is one idea × N with no progression and no turn.
- A throughline build that doesn't grow.
- Switching district worlds or minifig identity without narrative cause.
- A motif introduced but never paid off.

## Accept / Regenerate — Series Coherence

Accept: the set reads as one growing build in under ten seconds of scrolling; shared world, palette, minifig, and label style are visible across all images; each image has a distinct relation and role, none redundant; the build state progresses (N end = N+1 start); a motif appears, transforms, and pays off; intra-image chaining is clear (one route per image, minifig on it); removing or reordering any image would weaken the set.

Regenerate: images look like different product lines; the build state doesn't progress; the set is one idea repeated N times; the minifig resets to decorative standing or the label style jumps containers; the motif never pays off; the cross-image handoff is broken.

### Repair moves

If the set feels disconnected:
```text
Regenerate the series plan first. Lock the shared district world, brick palette, minifig identity, and label container. State the build-progression axis and each image's build state. Ensure image N end = image N+1 start before regenerating individual images.
```

If the build doesn't progress:
```text
Regenerate with an explicit construction axis (bare studs → half-built → tiled-done, or road reaches station 1 → final station). Each image must show a different build state with matching labels.
```

If the motif never pays off:
```text
Regenerate the resolution image so the recurring element returns transformed (the stamp lands, the bare slot is filled, the light brick glows). The reader should recognize it from image 1–2.
```
