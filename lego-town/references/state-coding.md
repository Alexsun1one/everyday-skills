# State Coding / 状态编码

State coding carries exact status — degree, stage, outcome, quality — with no extra words. Where `primitives.md` supplies the nouns, state coding supplies the precision: how each brick is colored, exposed, raised, or posed so its status reads instantly and consistently. Reusing the same encoding for the same state across a series is what lets a reader trust the builds.

Brick has a special gift here: **a bare stud is an unfilled slot, a tile cap is a finished surface, a transparent brick is a live signal.** Use the physical brick states first; reach for extra color only when needed.

Read with `style-dna.md` (palette, labels) and `primitives.md` (the elements these encodings attach to).

## Color Semantics / 色彩语义

Authentic brick colors, each meaning one thing; reuse across the set.

- **Dark/Light Bluish Gray · 灰** — structure, neutral mass, the unremarked baseline and the "done/inactive" background.
- **White · 白** — clean default / empty / not-yet-themed.
- **Tan / Dark Tan · 棕褐** — warm context, ground, "human/life" tone.
- **Bright Blue · 蓝** — the live route, current flow, the active reader path (the road that's "on").
- **Yellow · 黄** — attention, the thing to notice, a highlighted module.
- **Bright Green / Mint · 绿** — gain, healthy, passed, the positive change / finished-good module.
- **Red · 红** — failure, cost, stop, the risk part; a cracked or coral module.
- **Orange · 橙** — in-progress, warning, transitional, "under construction."
- **Transparent (clear / trans-color) · 透明件** — a live signal, energy, data, or "highlighted/selected"; trans-red = alarm, trans-green = go, trans-blue = active data.
- **One Focus Accent · 焦点色** — the single most important module; chosen per scene (often the only saturated color in a mostly-gray build).

Rule: keep ≤ ~5 strong colors active; exactly **one** focus accent — never two modules fighting for the eye. Always pair color with a physical state (stud-exposure, elevation, edge condition); color reinforces status, it never carries it alone.

## Stud & Surface States / 露点与表面状态 (the brick-native encoder)

- **Studs exposed / 露点** — an **open slot, unfinished, to-build, available to extend**; the most LEGO-native "TODO."
- **Tiled over (smooth cap) / 盖平滑片** — **finished, sealed, closed, done**; no more building here.
- **Half-built / 半成** — a module with some bricks placed and some slots still bare; "in progress."
- **Bricks loose / hovering** — not yet attached; proposed, optional, or being added (Instruction/Exploded modes).
- **Cracked / split brick / 裂砖** — damaged, broken, contested (pairs with red).
- **Re-snapped / patched / 补砖** — broken then repaired; a patch brick of a different color over a crack — recovery.

## Connection-State / 连接状态

- **Clutched tight / 扣紧** — a firm, confirmed dependency or link.
- **Resting (not clutched) / 虚搭** — a loose, proposed, or weak link (a brick set on top but not pressed in).
- **Bridged / 已桥接** — two modules actively connected by a road/coupling.
- **Gap / broken span / 断口** — a missing or failed connection.
- **Hinged / pivoting / 铰接** — a conditional or adjustable link.

## Elevation & Layering / 高度与层次

- **Raised / 抬高** — active, current, priority; the module is lifted on plates/pillars.
- **Recessed / built-down / 下沉** — background, inactive, or done; sits lower and quieter.
- **Stacked / 叠放** — hierarchy/dependency; higher layers rest on lower ones.
- **Overlap** — a brick lying over another reads as on top of / newer / masking it.

## Gate / Threshold States / 闸门状态

The barrier arm's posture is its verdict.

- **Up / 抬起** — pass; the road is open, items roll through.
- **Half / 半抬** — hold; conditional, partial, pending.
- **Down / 落下** — blocked or not yet reached.
- **Locked (with a 1×1 lock) / 上锁** — reject; hard stop.
- Pair with a **stamp tile** (通过 / 搁置 / 拒绝) only if the posture alone is ambiguous.

## Light & Emphasis / 光与强调

- **Lit / 受光** — present and legible.
- **Dim / 暗** — present but secondary.
- **Spotlight / 聚光** — the focus accent; the one module pulled forward.
- **Shadowed / 投影** — cost or footprint cast behind a module.
- **Trans-lit / 透光** — a transparent/light brick glowing to mark a live signal or selected part.

## Tile & Marker States / 标记状态

- **Filled vs outline tile** — filled = active/complete; outline/blank = pending/empty.
- **Stamp present** — a stamp tile = decided/passed; no stamp = unprocessed.
- **Color-grouped** — modules sharing a color belong to one path/category/team.
- **Sequence number** — a step badge or count tile shows order/position.

## Degree & Quantity / 程度与数量

Show amount with form, not numerals where possible.

- **Stack height** — taller = more accumulated.
- **Brick count** — a row of 1×1s, or a printed count tile (`×3`), shows quantity.
- **Module size** — bigger brick mass = more important / larger.
- **Slider position** — where the marker sits on the rail = the level.
- **Seesaw tilt** — the beam's lean shows which side outweighs.
- **Gauge needle** — the needle angle shows intensity/fill.
- **Hopper fill** — how full the funnel/bin is drawn shows quantity.

## Minifig Expression States / 小人仔表情状态

The minifig face is a state encoder too — original, abstract, used only when the state matters.

- **Neutral / 平静** — calm dot-eyes, flat line; the default.
- **Effort/Focus / 吃力·专注** — brows angled in, a tight mouth line; a hard build or careful inspection.
- **Strain/Warning / 受压** — brows pinched, a small down-line; near a red/cracked part.
- **Satisfaction / 落定** — eased brows, a small up-line; near a mint-green finished module or after a stamp lands.

Rules: one expression per minifig; original abstract strokes only (never a trademarked smiley, never realistic features); face turned toward the work; in a series, progress the expression with the build state.

## Encoding Budget / 编码预算

Do not stack encoders until the build screams.

- Pick the 1–2 encoders that carry the precision (e.g. **stud-exposure + one color**, or **elevation + a gauge**).
- Everything else stays neutral gray/tan/white brick, tiled-clean, evenly lit.
- A third encoder? Ask whether the system truly needs it or whether the build is becoming a dashboard.
- One focus accent, always.

## Accept / Regenerate

Accept: status reads in three seconds with no extra text; each color/stud-state/posture means one consistent thing across the set; ≤ ~5 strong colors and exactly one focus accent; only the encoders that carry the point are active; broken/bare/dim states mean something, never decoration.

Regenerate: two modules fight for the focus accent; too many simultaneous encoders read as a dashboard; a color or stud-state is decorative with no assigned meaning; status relies on tiny unreadable text instead of brick form/color/posture; encoders contradict (a "done" module lit brighter than the live one).
