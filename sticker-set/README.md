# Sticker Set / 表情包套图

> 把一个角色变成「能发出去」的一整套聊天表情包：微信表情、斗图表情、群里沙雕表情。

Sticker Set 面向所有想自己做表情包的普通人——给自家宠物、给一个原创小角色、给一个梗做成一套能在聊天里用的表情。它不是一个贴纸滤镜，而是一套表情包工作流：先锁死「这是同一个角色」，再保证「每一张都对得上一个真实的聊天瞬间」，最后生成一整套风格统一、能直接甩进对话框的表情。

表情包有两个硬任务：整套看起来是同一个角色（一致性），每一张都有人会在某个聊天瞬间发它（有用）。又一致又有梗，才是一套能用的表情包。

## 它解决什么问题

普通人做表情包常掉进几个坑：每张画风不一样（根本不像同一个角色）、只好看不实用（没有任何聊天场景会用到）、文字糊成一团（看不清写的啥）、画得恐怖（恐怖谷、脸崩了），还有最常见的——直接抄了别人的 IP（玲娜贝儿、蛋仔、宝可梦、LINE FRIENDS）。

Sticker Set 想要另一种状态：

- 一整套表情看起来就是同一个角色：同样的轮廓、配色、头型、线条粗细、同一个标志性小配件
- 每一张都对得上一个真实聊天瞬间：在吗、笑死、摆烂、已读不回、求饶、夸人、晚安
- 文字大、看得清、≤6 字、是网络口吻，不是书面语
- 白底或干净纯色底，方便抠图、直接当微信表情用
- 角色是原创的，不抄任何现成 IP

一句话判断：如果一张表情你想不出「在什么聊天瞬间会发它」，这张就还没做完。

## 适合谁

适合：想做微信表情、群聊斗图、沙雕表情、自家宠物表情、原创小 IP 表情的所有人。

不适合：单张封面图（用封面类 skill）、logo、正文插画、信息密集的数据图，以及任何「照着现有 IP 抄一套」的需求。

## 工作流

1. 读角色想法、吉祥物、宠物照片或梗。
2. 锁死角色 DNA：3–5 个在整套里都不变的固定特征。
3. 从 `references/expression-library.md` 选要覆盖的聊天瞬间（打招呼 / 赞同 / 拒绝 / 摆烂 / 打工累 / 委屈 / 求饶 / 笑死 / 已读不回 / 催 / 夸人 / emo / 吃瓜 / 晚安…）。
4. 定数量：一般 6–16 张。
5. 对每张跑「聊天瞬间测试」：用户在什么聊天瞬间会发这张？没有场景就砍掉。
6. 写文案：≤6 字、网络口吻、汉字正确。
7. 用 `references/style-dna.md` 定外观、配色、比例。
8. 用 `references/prompt-template.md` 先出「角色定妆图 / 表情九宫格」锁住身份，再从它派生每一张。
9. 一次生成一张，始终对照锁定的 DNA。
10. 用 `references/qa-checklist.md` 验收，跑偏、没场景、文字糊、抄 IP 就重做。

## 安装

### Codex

```bash
mkdir -p ~/.codex/skills
cp -R sticker-set ~/.codex/skills/sticker-set
```

重启后：

```text
用 $sticker-set 给我家这只橘猫做一套微信表情包，要在吗、摆烂、笑死、夸人这几个。先规划，先别生成。
```

### 其他 Agent（Claude Code / Cursor / Hermes / OpenClaw）

不需要 Codex Skill 格式，把 `SKILL.md` 和 `references/` 当作项目指令 / 规则 / workflow prompt 贴入即可。核心链路是：
`锁角色 DNA -> 选聊天瞬间 -> 聊天瞬间测试 -> 写文案 -> 先出定妆图 -> 逐张生成 -> QA`。

注意：跨 Agent 复用的是规划和提示词工作流；最终成图质量取决于图像模型，尤其是「一整套保持同一个角色」和「中文文案渲染」。角色跑偏时，按 `prompt-template.md` 从定妆图重新派生；中文文案渲染不干净时，先留空文案区、再在编辑器里叠字。
