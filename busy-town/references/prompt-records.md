# Prompt Records / 提示词留档

Use this reference for public examples, README/showcase images, article packages, client work, or any town likely to be reused.

Prompt records make Busy Town auditable and teachable — especially important when Chinese labels, exact step counts, and IP red lines are involved.

## Minimal Record

Save or report:

```text
asset name:
source anchor:
asset role:
relationship type:
mode + because:
lead animal / cast:
truth constraints:
reference cues:
final prompt:
output path:
rejected attempts:
QA result:
caption:
```

## Rejected Attempts

Record a rejected attempt when it teaches a reusable lesson:

- label misspelling / invented station
- decorative animals
- wrong metric or wrong step count
- copyright drift toward a Scarry likeness
- medium drift (3D / flat-vector / clay)
- too much in-image text
- crop or edge pressure
- too generic / fails Swap Test
- two-page delta loss
- cutaway-as-orgchart

Do not keep noisy notes for every ordinary draft.

## File Placement

For skill-package examples:

- put longer prompt records in `examples/` (e.g. `worked-examples.md` or a task-specific `PROMPTS.md`)
- put final full-resolution images in a project `examples/images/showcase/` if the outer package has one
- put compressed README images in `examples/images/readme/` when applicable

For article packages or external projects, use that project's asset folder.

## Why This Matters For Busy Town

- Chinese shop signs often need a second pass or post-overlay — record which path was used.
- Exact station counts are easy to invent under pressure — the record catches drift.
- IP red lines (no Scarry characters/scenes) need an audit trail when a user asked for a named character and you painted an original equivalent.
