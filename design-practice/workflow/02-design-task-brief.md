# Workflow 02 — 设计任务单模板(原文权威版,替代 stage1-task-card)

> 出处:《设计的实践》第 10 编 三(行 2127-2159)
> 定位:**每个项目开工前必填的"任务单",替代我之前自写的 stage1-task-card**
>
> **作者原话**:「不要迷信灵感。真正成熟的团队,开工前先把任务写清楚。一页设计任务单,比十句'做高级一点'有用得多。它不需要很长,但必须抓住核心。」

## 设计任务单完整模板(原文 verbatim)

```text
【页面 / 功能名称】

【用户是谁】
- 主要用户:
- 次要用户:
- 权限差异:

【核心任务】
用户来到这里,最重要要完成什么?

【成功标准】
怎样算完成?用户看见什么、点了什么、系统保存了什么?

【信息结构】
- 首屏必须出现:
- 可以折叠 / 延后:
- 必须隐藏到更多菜单:
- 不该出现在本页:

【组件与状态】
- 主要组件:
- 必须覆盖状态:
- 最危险的错误:
- 是否需要撤销 / 二次确认:

【响应式】
- 桌面:
- 平板:
- 手机:

【验收】
- 主任务走通:
- 状态完整:
- 可访问性:
- 坏数据:
- AI 自查:
```

## 为什么这模板比我之前的 Task Card 更权威

| 维度 | 我之前的 stage1-task-card | 原文设计任务单 |
|---|---|---|
| 字段数 | 10 | 7 大块,每块 3-5 子项 |
| 信息结构 | 没单独区分首屏/折叠/隐藏/不该出现 | **明确区分**(关键!) |
| 响应式 | 没单独写 | 桌面/平板/手机三块 |
| 验收 | 没单独写 | 主任务/状态/a11y/坏数据/AI 5 维 |
| 危险错误 | 没单独写 | "最危险的错误" + "是否撤销/二次确认" |

**关键升级**:**"不该出现在本页"** 这一行特别重要。它强迫设计师划边界,防止功能蔓延。

## 填写纪律

1. **每个字段都要填具体**,不能写"用户""页面""组件"。
2. **"不该出现在本页" 必填** — 这是边界,没边界的产品会胖。
3. **"最危险的错误" 必填** — 这是 P0 风险,没识别就不能开工。
4. **"是否撤销/二次确认" 必填** — 危险动作的护栏。
5. **响应式三块必填** — 不能只写桌面。

## 任务单的价值

> **作者原话(行 2159)**:「这张任务单的价值,是让每个人都知道'我们在做哪件事'。产品经理知道范围,设计师知道主次,工程师知道边界,AI Agent 知道约束。**没有任务单,会议上人人都能发表审美意见;有了任务单,讨论就会回到任务本身:这个意见是否帮助用户完成核心任务?**」

## 任务单 vs Intent Brief vs Anti-Plastic Test(三者的关系)

| 工具 | 何时填 | 解决什么 |
|---|---|---|
| **Intent Brief** | Stage 0 之前 | 用户要什么 + 风格 DNA |
| **Anti-Plastic Test** | Stage 0 之前 | 这一仗会怎么崩 |
| **设计任务单**(本文件) | Stage 0 之后,Stage 1 之前 | 具体怎么做、不做什么、怎么验收 |

**顺序**:Intent Brief → Anti-Plastic Test → 设计任务单 → Stage 1 五层切片。

## 反模式

### 反模式 1:任务单当摆设

```
坏的: 填了任务单,但开会还是讨论"按钮要不要圆一点"
病根: 任务单没成为决策依据。
```

### 反模式 2:字段填空话

```
坏的: "核心任务:让用户能高效完成任务"
病根: 没说具体是什么任务、谁是用户。
```

### 反模式 3:不填"不该出现在本页"

```
坏的: 这一行空着
病根: 没划边界,后期功能必然蔓延。
```

### 反模式 4:不填"最危险的错误"

```
坏的: 这一行空着
病根: P0 风险没识别,上线就出事。
```

## 提示词(让 AI 帮你填)

```text
你是产品经理 + 设计师。请基于下面信息,帮我填一份设计任务单,
每个字段必须具体,不能写空话。

产品:{...}
页面:{...}
已知用户反馈:{...}

请按以下模板填:

【页面 / 功能名称】
【用户是谁】主要/次要/权限差异
【核心任务】用户来这里最重要完成什么
【成功标准】用户看见什么、点什么、系统保存什么
【信息结构】首屏必须出现 / 可折叠延后 / 必须隐藏到更多 / 不该出现在本页
【组件与状态】主要组件 / 必须覆盖状态 / 最危险的错误 / 是否撤销二次确认
【响应式】桌面 / 平板 / 手机
【验收】主任务走通 / 状态完整 / 可访问性 / 坏数据 / AI 自查

要求:
- "不该出现在本页"必填,划清边界
- "最危险的错误"必填,识别 P0 风险
- 每个字段都要具体,不写"用户""页面"这种空词
```
