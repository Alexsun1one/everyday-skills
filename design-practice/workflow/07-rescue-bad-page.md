# Rescue Bad Page — 坏页面改造工作流（删/归/补/磨）

> 出处:原文行 2037:**"真实工作里,你很少从一张白纸开始,更多时候是接手一个已经很乱的页面。"**
>
> 这个工作流填补 skill 的盲区:现有所有流程（10 步、8 步、Stage 0/1/2）都是**从零生成**。但真实工作里,你拿到的更多是**内部烂后台 / 历史遗留页面 / 别人交付的塑料产物**。这种场景下走"10 步从零生成"是错的——你不该重画,你应该**改造**。

## 何时用这个工作流（intent routing）

| 用户场景 | 走哪条 |
|---|---|
| "做个 CRM 后台"（从零） | workflow/01 10 步流程 |
| "把这张截图改一下"（给已有页面） | **本文 改造四步** |
| "这个内部系统太乱了,帮我重做"（坏页面） | **本文 改造四步** |
| "Linear 风格的 dashboard"（从零） | workflow/01 + style-linear |
| "这个 dashboard 看着像 AI 写的,救一下"（塑料产物） | **本文 改造四步** |

**判断标准**:用户给了已有页面（截图 / HTML / Figma 链接）→ 走改造四步;用户只给了文字描述 → 走从零生成。

## 改造四步法（原文行 2049 verbatim，顺序不可调）

> 原文金句:**"注意顺序:先删,再归,再补,再磨。很多人反过来,页面还没理顺,就先换颜色、换字体、加阴影。这就像屋子里东西堆了一地,你不先收拾,先买一盏漂亮台灯。"**

```
删  →  归  →  补  →  磨
 ↑    ↑    ↑    ↑
 减法  整理  补洞  抛光
```

### Step 1 — 删（减法，最先做）

**目标**:把不该出现的东西砍掉。改造的第一步永远是减法,不是加法。

| 该删什么 | 怎么识别 | 删后做什么 |
|---|---|---|
| 重复的主按钮 | 一屏有 2 个 primary → 留主任务的那个,其余降级 secondary/ghost | 保留 1 个 primary |
| 装饰性元素 | 渐变背景、装饰图标、无用插画——不服务任务的 | 直接删 |
| 多余的列 | 表格有 12 列,用户只用 3 列 | 留 3 列,其余进抽屉/详情 |
| 历史遗留功能 | "这个功能 2 年没人用,但别删" → 删 | 删,真有人用再恢复 |
| 过度的视觉装饰 | 阴影、圆角、动画堆叠——服务和任务无关 | 删到只剩功能必需的 |

**反模式**:看到乱页面先加东西（加分隔线、加颜色、加分组框）——这会让乱的更乱。**先删。**

### Step 2 — 归（整理，删完才做）

**目标**:把剩下的东西归位。

| 该归什么 | 怎么归 |
|---|---|
| 信息层级 | 主任务 / 辅助 / 隐藏 → 三档分组,主任务占主区域 |
| 主按钮位置 | 一屏一个,放在主任务的视觉焦点（通常是右下、跟随表单、或空状态居中） |
| 操作分组 | 高频操作外露、中频进工具栏、低频进更多菜单 ⋯ |
| 状态分类 | loading / empty / error / permission / offline——每个数据模块都有这 5 态 |
| 反馈容器分类 | toast / inline / banner / modal——按"瞬时/就地/持久/阻断"分类,不混用 |

**反模式**:跳过"删"直接"归"——归一个还装满废料的房间,越归越乱。**删完才归。**

### Step 3 — 补（补洞，归完才做）

**目标**:把缺失的状态、组件、文案补齐。

| 该补什么 | 怎么补 |
|---|---|
| 状态 | 每个交互组件补 8 态（default/hover/active/focus/disabled/loading/success/error） |
| 数据状态 | 每个数据模块补 5 态（loading/empty-initial/empty-filter/empty-permission/error） |
| 权限矩阵 | viewer / editor / admin / author × 各操作 × 各状态 |
| 响应式 | 移动 / 平板 / 桌面 3 断点 |
| 深色模式 | 通过 token swap,不是另写一套 |
| 文案 | 把"操作失败"改成"网络断了,你的修改还在,再点一次就好" |
| a11y | focus ring / aria-label / focus trap / 对比度 |
| token 化 | 把写死的 #5E6AD2 改成 var(--color-primary) |

**反模式**:补完不验收——补的状态可能本身是塑料。**补完跑 qa-* 验收。**

### Step 4 — 磨（抛光，前三步全过才做）

**目标**:从"能用"到"顺"到"有气质"。

**前置 gate**:P0 / P1 / 五问 / 状态 / a11y / 响应式 / 坏数据全过。没过不准磨。

打磨项见 `references/qa-polish.md`（微文案 / 动效 / 空状态 / 表格密度 / 关键数字 / 成功危险反馈 / 页面节奏）。

**反模式**:跳级打磨。原文行 1862-1864:"**先把产品从'不可靠'做到'可靠',再从'可靠'做到'顺',最后从'顺'做到'有气质'。不要跳级。**"

## 范例：成员管理页改造（原文行 2051-2068）

原文给的范例页是这样的（坏样）:

```
成员管理页（坏样）:
- 顶部 8 个操作按钮（添加/批量删除/导入/导出/同步/刷新/设置/帮助）
- 表格 12 列（头像/姓名/邮箱/角色/部门/职位/电话/入职/状态/操作 1/操作 2/操作 3）
- 行内 5 个动作（编辑/删除/重置密码/禁用/转移部门）
- 失败只弹"操作失败"toast
- 空数据只显示"暂无数据"
- 没有加载骨架
- 删除直接执行,无确认
- 批量操作无选中态
```

改造后的样子（按删/归/补/磨）:

| 步骤 | 做什么 |
|---|---|
| **删** | 顶部 8 按钮 → 留"添加成员"主按钮,其余进 ⋯ 更多菜单。表格 12 列 → 留 5 列（头像/姓名/角色/部门/状态）,其余进详情抽屉。行内 5 动作 → 留"编辑"secondary,其余进 ⋯ |
| **归** | 主任务 = 管理成员。主按钮 = "添加成员"（右上）。批量操作选中后浮工具栏（删除/转移部门/改角色）。详情点行打开右侧抽屉。 |
| **补** | 8 态按钮。5 态数据模块（loading 骨架 / empty 三种 / error 就地 / permission banner / offline banner）。删除二次确认 + 撤销 toast。批量选中态。键盘可达。响应式（移动端表格转卡片）。 |
| **磨** | 微文案"操作失败" → "网络断了,3 个成员没删掉,你可以重试"。动效:抽屉从右滑入,详情打开时从行"长出"。空状态:initial 用引导插画 + "邀请第一个成员",filter 用筛选 chip + 清除,no-permission 用 banner。表格密度 5 秒扫 20 行。 |

## 和 10 步生成流程的接口

改造四步的"补"阶段,如果发现要补的状态/组件在 components/ 没有,可以走 10 步生成流程的 Stage 1/2 局部补。

改造四步的"磨"阶段,直接对接 `references/qa-polish.md`。

改造完成后的验收,走 `workflow/04-p0p1p2-review.md`（P0/P1/P2 三段评审）。

## 反模式（汇总）

| 反模式 | 阶段 | 修正 |
|---|---|---|
| 跳过"删"直接"归" | Step 2 | 回 Step 1,先删 |
| 跳过"补"直接"磨" | Step 4 | 回 Step 3,先补 |
| 改造时不验收 | 全流程 | 改造完跑 qa-p0p1p2 |
| 把改造当从零生成 | Intent | 给已有页面才走本文,从零走 workflow/01 |
| "删"得不够 | Step 1 | 原则:拿不准的就删,真有人投诉再恢复 |
| "归"时加装饰 | Step 2 | 归是整理,不是装饰;装饰留 Step 4 |
