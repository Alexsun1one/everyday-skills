# Workflow 04 — P0/P1/P2 评审分级(原文权威版)

> 出处:《设计的实践》第 10 编 五(行 2180-2191)
> 定位:**评审和自查的严格分级,替代模糊的"还可以/需要改"**
>
> **作者原话**:「设计评审最怕变成审美投票:我喜欢蓝色,你喜欢紫色;我觉得圆一点好,你觉得方一点高级;我觉得这里空,我觉得那里挤。这样的会开一小时,最后只收获一堆口味。」

## 评审四问(替代审美投票)

好的评审会围绕四个问题:

```
1. 这个设计是否服务核心任务?
2. 信息层级是否让用户少想一步?
3. 状态和边界是否可靠?
4. 视觉细节是否让体验更清楚、更稳定?
```

**纪律**:**所有"我觉得"必须能回答上面四个问题之一。回答不了的"我觉得"就是审美投票,作废。**

## P0/P1/P2 严格定义(原文 verbatim)

| 等级 | 定义 | 例子 | 评审原则 |
|---|---|---|---|
| **P0** | **会让任务失败** | 提交失败丢内容、删除无确认、权限错误导致看不到关键入口、重复点击建多条、必填项无校验、移动端核心功能崩 | **P0 没修完,不要争 P2;主流程没走通,不要争阴影** |
| **P1** | **明显影响效率和理解** | 主按钮不清、筛选太重、错误提示含糊、移动端难用、加载时间过长无骨架屏、状态混淆、信息密度过高 | **P1 必须在本版本修** |
| **P2** | **精致度优化** | 动效更自然、微文案更亲和、间距再稳一点、配色微调、图标对齐、hover 反馈更细腻 | **P2 可以排到下版本** |

## 为什么用 P0/P1/P2(而不是"高分/低分"或"严重/中等/轻微")

```
"严重 / 中等 / 轻微"            P0 / P1 / P2
─────────────────               ─────────────────
主观,容易吵                     客观,有明确判断标准
"我觉得这个挺严重"               "这是 P0:会让主任务失败"
→ 吵一小时                      → 30 秒决断
```

**P0/P1/P2 的本质**:把"我感觉"翻译成"对用户的具体伤害"。

## P0 判定标准(详细)

**任何符合下面任一条 = P0**:

1. **主任务走不通**:用户完成不了核心任务(如登录页登不进去、支付页付不了款、列表页加载不出)
2. **数据丢失**:用户输入/工作成果会丢(如表单提交失败丢内容、关闭抽屉丢草稿)
3. **数据错乱**:重复提交、并发冲突、状态不同步(如点 3 次创建 3 条)
4. **危险动作无护栏**:删除/支付/退出无确认或无撤销
5. **权限错配**:用户能看到不该看的、不能看到该看的、能改不该改的
6. **移动端核心功能崩**:在主流手机上主任务走不通
7. **无障碍阻断**:键盘用户/读屏用户根本用不了(如 focus ring 删了)
8. **错误像系统日志**:错误文案用户看不懂、不知怎么修
9. **状态缺失导致误操作**:如未保存提示缺失,用户以为保存了就退出

## P1 判定标准(详细)

**符合下面任一条 = P1**:

1. **主行动不唯一**:多个蓝色按钮抢戏(参考 SKILL.md One-Primary-Action Test)
2. **信息层级混乱**:权重 5 的元素超过 3 个
3. **筛选过重**:默认铺出 10+ 筛选项(违反渐进披露)
4. **加载无反馈**:超过 0.4 秒无骨架屏(违反多尔蒂)
5. **错误文案含糊**:"操作失败" / "出错了" / "请稍后"
6. **空状态没引导**:只写"暂无数据"(违反第三分类)
7. **响应式不重排**:移动端只是桌面端缩小
8. **微交互塑料感**:hover 只变色,无 pressed / focus 反馈

## P2 判定标准(详细)

**符合下面任一条 = P2**:

1. **动效不够自然**:缓动曲线生硬、时长不一致
2. **微文案可以更亲和**:错误文案可以更人话
3. **间距不够稳**:有几个地方没遵守 4px 网格
4. **配色微调**:某处对比度刚好卡 4.5:1 边缘
5. **图标对齐**:有几个图标和文字基线没对齐
6. **hover 反馈可以更细腻**:可以加 scale / shadow
7. **动画节奏**:页面切换的节奏可以更流畅

## 评审会流程(P0/P1/P2)

```
1. 主持人按"评审四问"开场,所有人不准说"我觉得"
2. 每条问题按 P0/P1/P2 分类
3. P0 必修,现场确认修复方案 + 负责人 + 截止时间
4. P1 必修,本版本内修复
5. P2 排到下版本
6. 散会前确认所有 P0 有 owner
```

**纪律**:**P0 没修完,不要争 P2;主流程没走通,不要争阴影;错误态会丢内容,不要争插图风格。团队时间很贵,要先打要害。**

## 自查提示词(让 AI 按 P0/P1/P2 挑刺)

```text
你是一位严格的产品评审。请按 P0/P1/P2 分级审查这个页面,
不要给"我觉得",每条问题必须说"对用户的具体伤害"。

页面:{截图/代码/描述}
核心任务:{用户来这一页要办的事}

请输出:
- P0 问题清单(会让任务失败的):每条 = 问题 + 对用户的具体伤害 + 修复建议
- P1 问题清单(明显影响效率的):每条 = 问题 + 修复建议
- P2 问题清单(精致度优化):每条 = 问题 + 修复建议
- 总评:P0 数量、P1 数量、P2 数量 + 是否可以上线

纪律:
- P0 不修完不准上线
- P1 必须本版本修
- P2 可以排到下版本
- 不写"高级感""现代感"这种空词,必须说具体
```

## 反模式

### 反模式 1:审美投票

```
坏的: 评审会变成"我觉得蓝色好看""我觉得圆角更高级"
病根: 没用 P0/P1/P2,用了"我觉得"。
```

### 反模式 2:小问题当大问题

```
坏的: 把"间距差 2px"当 P0,大讨论一小时
病根: P0/P1/P2 没分清,这其实是 P2。
```

### 反模式 3:大问题当小问题

```
坏的: "删除无确认"标成 P2
病根: 这是 P0(危险动作无护栏)。
```

### 反模式 4:P0 没修完就上线

```
坏的: P0 还有 3 个没修,先上线 P2 改了
病根: 团队时间错配,P2 优先级不该高过 P0。
```

### 反模式 5:让 AI 自评

```
坏的: AI 说"看起来不错,可以上线"
病根: 没让 AI 出示 P0/P1/P2 清单 + 具体证据。
```
