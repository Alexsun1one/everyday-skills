## 盲点 1:AI 自审 prompt(让 AI 切换评审员角色挑刺)

- **原文出处**:第 28 章,行 906-935,原文摘抄:"**让 AI 先写，再让 AI 自己挑刺**...请切换成一位苛刻的产品设计评审，不要夸自己刚才的输出。"
- **方法论**:大模型不怕返工,人怕。利用这一点建立"运动员 → 裁判员"的两步 loop:第一步生成规范,第二步立刻切换成苛刻评审角色,逐条挑刺,输出"问题列表 / 为什么是问题 / 应该怎么改 / 修改后的最终版本"。
- **关键数据**:原文给的 8 项检查清单:
  1. 有没有空话套话?
  2. 有没有没有数值的规范?
  3. 有没有组件只写了默认态?
  4. 有没有漏掉 loading / empty / error / permission denied / offline 状态?
  5. 有没有违反"一屏一个主按钮"?
  6. 有没有把复杂任务塞进模态?
  7. 有没有直接写死颜色值,而不是使用语义令牌?
  8. 有没有缺少可访问性和键盘操作要求?
- **案例**:原文行 913-929 给了完整 prompt 模板(切换评审角色 + 8 项检查 + 4 段输出)。
- **提示词模板**:
  ```
  现在请你切换成一位苛刻的产品设计评审，不要夸自己刚才的输出。
  请逐条检查:[上面 8 项]
  请输出:
  - 问题列表
  - 为什么是问题
  - 应该怎么改
  - 修改后的最终版本
  ```
- **检查清单**:产物是否经过了"角色切换 + 8 项检查 + 4 段输出"的 loop?还是只生成一稿就交付?
- **现有 skill 是否已冻结**:**否**。`references/qa-*` 系列(qa-state-acceptance / qa-three-gates / qa-a11y / qa-bad-data / qa-responsive / qa-p0p1p2)是**对产物的验收清单**(产物层),不是**让 agent 自己切换角色挑刺的 prompt**(生成层)。两个层级不同:qa-* 是"交付前检查",原文这个是"生成中自审 loop"。
- **建议**:**新增** `references/ai-self-review-loop.md`,冻结原文行 913-929 的评审员 prompt + 8 项检查 + 4 段输出格式。明确写清"和 qa-* 的区别:qa-* 验收产物,本文件是生成 loop 的第二步"。

## 盲点 2:任务级反馈链(click → pressed → loading → success/error 的时间轴)

- **原文出处**:第 17 章,行 640-654,原文摘抄:"**按下去有 pressed 态，提交时按钮进入 loading，成功后按钮恢复并给 toast 或页面状态更新，失败后保留输入并就地说明原因。**"
- **方法论**:用户点一个按钮,心里走 4 个问题:(1) 我点到了吗?(2) 系统开始处理了吗?(3) 处理成功了吗?(4) 失败该怎么办?好设计一层一层回应,整个过程像有人在旁边接话:"收到,正在办,办好了;没办成,原因在这里,东西没丢。"
- **关键数据**:反馈四问 + 反馈时间轴:
  - <100ms:pressed 态(我点到了)
  - 100-1000ms:loading 态(正在办)
  - 完成时:toast / 页面状态更新(办好了)
  - 失败时:保留输入 + 就地说明原因(没办成,东西没丢)
- **案例**:原文行 652 用"保存按钮"做例子:差设计"点一下没变化,过几秒页面跳一下,失败时弹一句操作失败";好设计"pressed → loading → 成功 toast / 失败保留输入就地说明"。
- **提示词模板**:
  ```
  为这个操作设计任务级反馈链(不是单个微交互):
  - <100ms:pressed 态该长什么样?
  - 100-1000ms:loading 态该长什么样?按钮 disabled 防 re-click 了吗?
  - 成功:反馈在哪(toast / 页面状态 / inline)?会不会太吵?
  - 失败:输入保留了吗?错误就地说明还是跳到别处?有没有撤销/重试?
  ```
- **检查清单**:
  - □ 按钮有 pressed 态吗?
  - □ 提交时进入 loading 且 block re-click 了吗?
  - □ 成功后反馈位置对吗(toast 用于轻提示,inline 用于状态更新)?
  - □ 失败时输入保留了吗?错误就地说明了吗?
- **现有 skill 是否已冻结**:**部分**。`stage2-button-8-states.md` 按"按钮 8 态"冻结,`stage2-microinteractions.md` 按"四件套(trigger/rule/feedback/loop)"冻结。但**两者都是微观视角**(单个状态/单个交互),**没有"任务级反馈时间轴"视角**——从 click 到 success/error 的完整链路,每一段该给什么反馈。原文行 654 的"保存按钮"例子横跨 4 个状态,是任务级的,不是微交互级的。
- **建议**:**新增** `references/stage2-feedback-chain.md`,冻结"反馈四问 + 时间轴 + 好坏对照"。明确写清"和 stage2-button-8-states / stage2-microinteractions 的区别:那两个是微观状态/交互,本文件是任务级时间轴"。
- **优先级**:**P1** — 原文用了一整章讲,现有 skill 有零件没组装。

## 盲点 3:坐标感(面包屑/导航高亮/返回逻辑/保留列表滚动位置)

- **原文出处**:第 24 章,行 817-819,原文摘抄:"**不要小看"返回后还在原来的列表位置"这种细节，它会让用户觉得产品懂他。**"
- **方法论**:信息架构第 3 条硬规矩——用户要随时知道自己在哪里、从哪里来、能回哪里去。坐标感由 5 个细节组成:(1) 面包屑;(2) 当前导航高亮;(3) 清晰标题;(4) 返回逻辑;(5) **保留列表滚动位置**。
- **关键数据**:5 个坐标感细节,其中"保留列表滚动位置"是反塑料锚点(AI 容易漏)。
- **案例**:用户在任务列表滚到第 50 条,点进详情,返回后——差设计:列表回到顶部,用户得重新滚;好设计:列表还在第 50 条,用户无缝继续。
- **提示词模板**:
  ```
  为这个页面检查坐标感 5 件套:
  - 面包屑(用户在哪一层)?
  - 当前导航高亮(用户在哪个模块)?
  - 清晰标题(用户在干什么)?
  - 返回逻辑(用户从哪来,能回哪去)?
  - 列表滚动位置保留(返回后还在原位吗)?
  ```
- **检查清单**:
  - □ 进入详情再返回,列表滚动位置保留了吗?
  - □ 当前导航项有高亮吗?
  - □ 多层路径有面包屑吗?
  - □ 页面标题清晰描述当前任务吗?
- **现有 skill 是否已冻结**:**否**。`patterns/03-container-decision.md` 讲了容器的"必须保留上下文",但**没点名"列表滚动位置保留"这个具体细节**。`design-judgment/01-task-field.md` 的"用户路径图"提到"出口",但没展开坐标感 5 件套。这是 AI 产物非常容易漏的塑料信号(返回后列表回到顶部 = AI 味)。
- **建议**:**新增** 到 `patterns/03-container-decision.md` 或单独建 `patterns/07-spatial-continuity.md`,冻结坐标感 5 件套 + 反塑料锚点。
- **优先级**:**P1** — 原文明确点名这是反塑料锚点,现有 skill 完全缺失。

## 盲点 4:坏提示词 vs 好提示词的对照诊断

- **原文出处**:第 27 章,行 867-904,原文摘抄:"**坏提示词长这样:帮我写一套好看的 SaaS 设计规范，要高级一点，参考 Linear 和 Stripe。**"(行 872)
- **方法论**:坏提示词和好提示词的差,不在"高级词"多少,而在**靶子清不清楚**。坏提示词的问题:用户是谁不知道、产品干什么不知道、页面类型不知道、组件范围不知道、是否有暗色模式不知道、状态要不要补不知道、输出格式也不知道——模型只能靠想象补洞,补得越多越危险。好提示词给齐角色/背景/任务/约束/输出格式 5 样,模型就不容易乱跑。
- **关键数据**:原文给了完整的"坏 vs 好"对照(行 871-902),坏提示词 1 行,好提示词带 6 条约束 + 5 段输出格式。
- **案例**:坏:"帮我写一套好看的 SaaS 设计规范,要高级一点,参考 Linear 和 Stripe。" 好:见行 880-901(角色 + 背景 + 任务 + 6 条约束 + 5 段输出格式)。
- **提示词模板**:
  ```
  诊断下面的提示词是"坏"还是"好":
  - 用户是谁? (缺 = 坏)
  - 产品干什么? (缺 = 坏)
  - 页面类型? (缺 = 坏)
  - 组件范围? (缺 = 坏)
  - 暗色模式? (缺 = 坏)
  - 状态要不要补? (缺 = 坏)
  - 输出格式? (缺 = 坏)
  缺 ≥3 项 = 坏提示词,必须补齐 5 要素再生成。
  ```
- **检查清单**:见上面 7 项诊断点。
- **现有 skill 是否已冻结**:**部分**。`prompt-templates.md` 的 Template 1 给了好提示词的完整模板,但**没有"坏提示词"的反面教材**,也没有"7 项诊断点"让 agent 自查自己的 prompt 是不是坏提示词。`intent-reading.md` 的"常见意图误读警示"讲了用户描述的误读,但不是 prompt 质量诊断。
- **建议**:**修订** `prompt-templates.md`,在开头加一段"坏提示词 vs 好提示词"对照 + 7 项诊断清单。让 agent 在套模板前先诊断自己的 prompt 是不是坏的。
- **优先级**:**P1** — 这是诊断工具,能阻止 agent 用坏 prompt 生成塑料产物。

## 盲点 5:跨工具分工矩阵(找料-推理-成文-落库)

- **原文出处**:第 29 章,行 937-947,原文摘抄:"**Perplexity 适合找料...ChatGPT、Claude、Gemini 这类通用大模型适合推理和改写...Notion AI 适合成文和落库。**"
- **方法论**:会写字的 AI 也有分工,不要让所有工具干同一件事。四步分工:(1) 找料(Perplexity,调研员,查 Material 动效时长 / Apple 点击热区 / WCAG 对比度 / Atlassian 设计令牌);(2) 推理改写(ChatGPT/Claude/Gemini,写手,把资料变原则、变结构、变提示词);(3) 成文落库(Notion AI,编辑和档案管理员,变团队规范页);(4) 错误用法是让 AI 凭感觉写权威规范,正确用法是先调查再成文再审稿再落团队流程。
- **关键数据**:4 步分工 + 每步对应工具 + 每步角色比喻(调研员/写手/档案管理员)。
- **案例**:原文行 941-945 给了 3 个工具的具体用法。
- **提示词模板**:
  ```
  跨工具分工矩阵:
  | 步骤 | 工具 | 角色 | 产出 |
  | 找料 | Perplexity | 调研员 | 带出处的资料 |
  | 推理 | Claude/ChatGPT | 写手 | 原则/结构/提示词 |
  | 成文 | Notion AI | 档案员 | 团队规范页 |
  | 落库 | Notion/GitHub | 档案员 | 可复用文档 |
  ```
- **检查清单**:
  - □ 设计规范是不是凭感觉写的?(应该先 Perplexity 找料)
  - □ 找来的料有没有出处?(Perplexity 强制带来源)
  - □ 推理时有没有给清楚边界?(否则通用模型写漂亮作文)
  - □ 成文后有没有落进团队流程?(不是只在聊天里)
- **现有 skill 是否已冻结**:**否**。`agent-playbook.md` 是 **design-practice skill 内部的 11 步执行流程**(skill 内),**没有讲跨工具分工**——什么时候该跳出这个 skill 去用 Perplexity 找料,什么时候该把产出落到 Notion。这是元方法论,影响工作流质量。
- **建议**:**新增** `references/tool-division.md`,冻结 4 步分工矩阵。明确写"agent-playbook 是 skill 内流程,本文件是跨工具分工,两者正交"。
- **优先级**:**P1** — 原文独有,影响工作流实操,但不直接影响单次产物 AI 味。

## 盲点 6:转场四类分类表(按"转场类型"而非"元素"分类)

- **原文出处**:第 20 章,行 695-709,原文摘抄:"**转场最重要的任务，是建立空间关系。**"(行 697)
- **方法论**:转场分 4 类:(1) 进入(元素出现);(2) 退出(元素消失);(3) 状态切换(同类元素变状态);(4) 层级移动(从列表到详情、从主任务到子任务)。每类的空间逻辑不同。
- **关键数据**:原文给了 4 个元素级例子(抽屉从右/Popover 从按钮附近/模态居中遮罩/Toast 从边缘),对应不同转场类型。
- **案例**:列表点详情 = 层级移动(详情从列表项"长"出来,返回回原位)。
- **提示词模板**:
  ```
  这个转场属于哪一类?
  - 进入(元素首次出现)
  - 退出(元素消失)
  - 状态切换(同类变状态)
  - 层级移动(主→子任务,详情从父元素长出)
  每类的空间逻辑不同,选错就违和。
  ```
- **检查清单**:
  - □ 转场方向匹配空间逻辑吗?
  - □ 层级移动时,子页面从父元素长出吗?返回时回原位吗?
- **现有 skill 是否已冻结**:**部分**。`stage2-motion-discipline.md` 的 "Direction (spatial logic)" 表**按元素分**(drawer/modal/tooltip/toast/dropdown/list item),实操够用。但**没有按"转场类型"分的四类表**——这是补充视角,不是新内容。
- **建议**:**修订** `stage2-motion-discipline.md`,在 Direction 表后加一小段"转场四类分类",把元素对照到转场类型。优先级低,因为按元素分的表已经够实操。
- **优先级**:**P2** — 现有按元素的表已覆盖实操,这是组织视角的补充。

## 盲点 8:通用提示词模板的"产品气质"+"关键业务风险"字段

- **原文出处**:第 30 章,行 956-968,原文摘抄:"**产品气质:**"(行 961)+"**关键业务风险:**"(行 967)

- **关键数据**:2 个字段。
- **案例**:产品气质 = "效率、清晰、克制、快捷键友好"(行 883);关键业务风险 = "用户填一半网络断了,草稿丢了吗?"

- **检查清单**:
  - □ 提示词里有"产品气质"字段吗?(影响风格路由)
  - □ 提示词里有"关键业务风险"字段吗?(影响反塑料重点)
