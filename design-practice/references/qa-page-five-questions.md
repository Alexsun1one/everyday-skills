# 页面验收五问 — Page-Level QA

> 这是页面级的最后一道质量门。**任何一页生成完,都要过这五问**——五问任何一条答不上来,这一页就是失败的,无论组件做得多精致。
>
> AI 生成 UI 最常见的失败模式:**组件都对,但页面整体没有叙事、没有焦点、不知道要用户干什么**。这五问强制把"用户视角"塞回验收环节。

## 五问

打开生成完的页面,作为一个**第一次来的真实用户**,问自己:

### 1. 我是谁?(Who am I?)

> 用户进入这一页,他能不能在 3 秒内知道:**这是哪个产品、哪个区域、哪个角色**?

**失败的页面症状:**
- 没有 logo / 没有 page title
- breadcrumb 缺失,用户不知道自己在 IA 哪一层
- 角色不明显(普通用户看到的内容和管理员看到的一样,没区分)
- 视觉上和别的页面完全没继承,像从别的网站跳过来的

**通过的页面证据:**
- 顶栏有 logo + 产品名
- 有 page title 或 breadcrumb 说明当前位置
- 导航高亮当前位置
- 角色权限反映在可见元素上(管理员看到"管理"按钮,普通用户看不到)

### 2. 给谁?(For whom?)

> 这页是给哪个 audience 的?**视觉决策匹配 audience 吗**?

**失败的页面症状:**
- 给"消费者"的页面用了 Linear 深色工程感(冰冷、难懂)
- 给"开发者"的页面用了 Notion 奶油温暖感(显得不专业)
- 给"管理员"的页面用了营销落地页风格(信息密度不够)
- 字号、行距、术语水平不匹配 audience

**通过的页面证据:**
- 风格 DNA 与 audience 匹配(查 `intent-reading.md` 路由表)
- 术语水平匹配 audience 知识水平
- 字号 / 间距匹配 audience 偏好(消费者大字号大间距,管理员密集)

### 3. 干什么?(What's the task?)

> 用户进入这页,**他要做的一件事是什么**?能不能在 5 秒内识别?

**失败的页面症状:**
- 页面有 5+ 个并列的 primary CTA,不知道主推哪个
- 页面没有明确的"主要任务"——全是信息展示
- 主要 CTA 颜色和次要 CTA 一样,视觉无层级
- 任务 buried 在信息堆里,要滚动 3 屏才能找到

**通过的页面证据:**
- 每屏只有 **一个** primary CTA(其他都是 secondary/ghost)
- 主要任务在视觉焦点(顶部、最大按钮、最显眼颜色)
- 页面有清晰的 "task hierarchy":主任务 → 次任务 → 阅读
- 即使是 dashboard,也有 "现在最该做什么" 的视觉提示

### 4. 下一步?(What's next?)

> 用户完成当前任务后,**自然去哪**?有没有清晰的下一步路径?

**失败的页面症状:**
- 任务完成后页面"死"了,不知道接下来做什么
- success state 没有"继续"或"完成"的 CTA
- 表单提交后只显示一个 "Success" toast,没有下一步
- 流程页面之间没有顺承(填完 step 1 不知道 step 2 在哪)

**通过的页面证据:**
- success state 有明确的下一步 CTA("查看结果"、"继续下一步"、"返回列表")
- 流程页面有进度条 + 自动跳转到下一步
- 错误状态有"重试"、"联系支持"、"返回上一步"等明确出口
- 空状态有"创建第一个 X"的引导 CTA

### 5. 不能做时?(What if it fails?)

> 用户**不能完成**任务时(没权限、网络断、数据为空、表单错误),页面怎么处理?

**失败的页面症状:**
- 网络断了页面白屏
- 没权限显示"403 Forbidden"裸文字
- 数据为空显示一个空 div
- 表单错误只显示一个红色边框,没说为什么错
- 服务器 500 显示 stack trace

**通过的页面证据:**
- 空状态有插画 + 解释 + CTA(`empty-state.md`)
- 错误状态有三件事:发生了什么 + 为什么 + 怎么办(`qa-state-acceptance.md`)
- 无权限页面解释需要什么角色 + 联系管理员 CTA
- 网络断了有 retry CTA
- 加载状态有 skeleton 或 spinner,不是白屏

## 验收清单(每条打勾才算过)

```text
页面 URL: _____________
验收人: _____________
日期: _____________

□ 1. 我是谁?
  □ 3 秒内能识别产品 / 区域 / 角色
  □ 有 logo + page title + breadcrumb
  □ 角色权限反映在可见元素

□ 2. 给谁?
  □ 风格 DNA 匹配 audience(查 intent 路由表)
  □ 术语匹配知识水平
  □ 字号 / 间距匹配偏好

□ 3. 干什么?
  □ 每屏只有一个 primary CTA
  □ 主任务在视觉焦点
  □ 有 task hierarchy(主→次→阅读)

□ 4. 下一步?
  □ success state 有下一步 CTA
  □ 流程有进度条 + 自动顺承
  □ error state 有重试 / 联系支持 / 返回

□ 5. 不能做时?
  □ 空状态有插画 + 解释 + CTA
  □ 错误状态三件事:what + why + how
  □ 无权限有解释 + 联系管理员
  □ 网络断有 retry
  □ 加载有 skeleton / spinner
```

## AI 验收员提示词(用 AI 跑这五问)

把这个提示词喂给 AI,让它对生成的页面打分:

```text
你是一个严格的 UI 验收员。审查下面这个页面,从用户视角回答五问。

页面 URL / 截图:[提供]

对每一问打分(1-5 分)并解释:

1. 我是谁?(3 秒内能识别产品/区域/角色?)
2. 给谁?(风格 DNA 匹配 audience?术语匹配知识水平?)
3. 干什么?(每屏只有一个 primary CTA?主任务在视觉焦点?)
4. 下一步?(success 有下一步?流程有顺承?error 有出口?)
5. 不能做时?(空状态?错误三件事?无权限?网络断?加载?)

任何一问低于 4 分,这个页面就是失败的,要明确指出修复点。

不要给"还行"、"可以"这种模糊反馈。要具体到组件、像素、文案。
```

## 坏页面症状库(快查)

| 症状 | 五问哪条挂了 | 修复 |
|---|---|---|
| "看起来不错,但不知道是哪个产品" | 1. 我是谁 | 加 logo + product name |
| "太冷冰冰了" | 2. 给谁 | 风格 DNA 路由错了,改 Notion |
| "我不知道这页是干嘛的" | 3. 干什么 | 明确 primary CTA,移除多余 CTA |
| "填完了不知道接下来干嘛" | 4. 下一步 | 加下一步 CTA 或自动跳转 |
| "数据没了我傻眼" | 5. 不能做时 | 加空状态 |
| "出错了不知道为什么" | 5. 不能做时 | 错误三件事:what + why + how |
| "页面太花不知道点哪" | 3. 干什么 | 主次 CTA 视觉分层 |
| "感觉像通用模板" | 2. 给谁 | 风格 DNA 没真正用,只是套了皮 |

## 与其他 QA 文档的关系

- **页面五问** 是页面级总验收(这一页)
- **状态验收** `qa-state-acceptance.md` 是组件级状态验收(loading/empty/error/etc)
- **a11y** `qa-a11y.md` 是无障碍验收(键盘/屏幕阅读器/对比度)
- **响应式** `qa-responsive.md` 是多端验收(桌面/平板/手机)
- **坏数据** `qa-bad-data.md` 是边界数据验收(超长/空/极端)
- **建议顺序**:页面五问 → 状态验收 → a11y → 响应式 → 坏数据
