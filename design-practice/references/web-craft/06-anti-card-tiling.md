# 06 — 反卡片平铺(AI 网页最大的塑料 tell)

> ⭐ 本文件是 web-craft 的核心。AI 生成的"网页"有一个指纹般一致的默认动作:**把任何"要展示一堆东西"的地方都做成 3 列(或 2×3)等宽 icon 卡片网格**。每张卡一个彩色圆角方块里塞个 lucide 图标 + 一个标题 + 一句废话描述,六张全等大、等 padding、等字数。这是 2023-2026 最浓的网页塑料味,也是顶级网页与 AI 网页分叉的第一道关。本文件命名这个敌人,并给 6 套替代的高级布局系统。

## 0. 先认清敌人:卡片平铺长什么样、为什么塑料

### 它长这样(AI 默认)
```
┌──────────┐  ┌──────────┐  ┌──────────┐
│  ⚡(圆圈) │  │  🔒(圆圈) │  │  🚀(圆圈) │
│  Fast    │  │  Secure  │  │  Scalable│
│  极速响应 │  │  安全可靠 │  │  弹性扩展 │
│  描述一句 │  │  描述一句 │  │  描述一句 │
└──────────┘  └──────────┘  └──────────┘
```
3 列等宽,每张:彩色圆角方块包 lucide 图标 + 短标题 + 一句 lorem 式描述。六张全等大、等 padding、等字数、等图标处理。

### 为什么它是塑料(四条病根)
1. **没有信息层级**——每张卡等权 = 没有任何一张重要。用户视线无处落脚,只能逐张扫,扫完什么都没记住。(`design-judgment/04-visual-hierarchy.md` 的"一屋子人同时喊"。)
2. **没有密度对比**——真实信息不平等:有的功能是主角需要大图详述,有的是配角一句话带过。卡片平铺把它们全塞进一样的盒子,逼主角和配角同框。
3. **没有构图意图**——它是"一堆盒子",不是"一个设计"。它在说"我有 6 个东西要展示,所以我做了 6 个盒子"。
4. **圆圈包图标是最响的 tell**——每张卡顶部一个彩色圆角方块里塞 lucide 图标。这个 motif 重复 6 次 = 在标题写"AI 生成"。

> **判断你的 feature 区是不是塑料:把六张卡的标题遮住,还能不能分出哪张是哪张?** 不能 = 它们是克隆,不是设计。

## 1. 编辑型不对称栅格(有一个"主菜")

### 构思
别用等宽列。用**有一个 lead(主菜)+ 配菜**的不对称栅格:主菜占 2× 宽(或 2× 高),配一张真实大截图 + 较长文案;其余配角小一号、文案短。**层级来自尺寸差**——主菜明显大,配菜明显小。

### ASCII
```
┌──────────────────────────┬─────────────┐
│                          │             │
│   主功能 (lead)           │  配功能 A   │
│   ┌──────────────────┐   │  (短)       │
│   │                  │   ├─────────────┤
│   │   真实产品截图    │   │             │
│   │   (大, 占视觉)    │   │  配功能 B   │
│   │                  │   │  (短)       │
│   └──────────────────┘   │             │
│   大标题 + 2-3 行详述      │             │
│                          │             │
└──────────────────────────┴─────────────┘
```

### CSS
```css
.features {
  display: grid;
  grid-template-columns: 2fr 1fr;   /* 主菜 2 倍宽 */
  grid-template-rows: auto auto;
  gap: 24px;
}
.lead { grid-row: span 2; }          /* 主菜占两行高 */
.support { /* 配菜,更小 padding,更短文案 */ }
```

### 何时用
你有一个**明确的主角功能** + 几个配角。主角需要截图/大图详述,配角一句话带过。

### 它凭什么比卡片平铺高级
卡片平铺逼所有功能"装作平等";不对称栅格**承认不平等**——主角占大位、配菜占小位,用户视线自然先落主角,层级清晰。真实信息从来就不平等,布局该反映这一点。

## 2. Bento 的正确做法(大小对比 + 密度对比)

### 构思
Bento(便当盒,Apple/Vercel 带火)是**不同尺寸格子**拼成的栅格。但 90% 的 AI bento 是塑料的——格子尺寸略不同,但每格内容类型一样(还是图标+标题+描述),只是盒子形状不规整。**那仍是卡片平铺,只是盒子歪一点。**

**真 bento 的两条命脉**:
1. **尺寸对比**——格子明显不同大(有的占 2×2,有的占 1×1)。
2. **密度/内容对比**——每格是**不同类型的内容**:一格是大视觉(低密度高冲击),一格是密集数据块(高密度),一格是 feature+小图表,一格是大引用。每格是便当里"一道不同的菜",不是六道一样的菜。

### ASCII
```
┌────────────────┬─────────────────────────┐
│                │                         │
│  大视觉格       │   数据/统计格(密集)     │
│  (产品全貌截图) │   99.9% uptime           │
│  低密度 高冲击   │   3 regions · 38ms p95   │
│                ├────────────┬────────────┤
├────────────────┤            │            │
│  feature 格     │  图表格     │  引用格     │
│  + 小说明        │  (mini     │  “一句客户  │
│  + 真实数据      │  chart)    │   证言”)   │
└────────────────┴────────────┴────────────┘
```

### CSS
```css
.bento {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  grid-auto-rows: minmax(140px, auto);
  gap: 16px;
}
.bento .visual    { grid-column: span 2; grid-row: span 2; }
.bento .stats     { grid-column: span 2; }
.bento .chart     { grid-column: span 1; }
.bento .quote     { grid-column: span 1; }
```

### 何时用
展示一个产品的**多个侧面**,且每个侧面值得不同对待(有的要大图、有的要数据、有的要图表、有的要证言)。

### 它凭什么比卡片平铺高级
卡片平铺是六道一样的菜;真 bento 是**每格内容决定格子尺寸**——大视觉配大格,密集数据配紧凑格,引用配呼吸格。**尺寸服务于内容**,不是内容迁就格子。

> **bento 防塑料自检:遮住每格的标题,还能不能靠"格子大小 + 内容类型"区分它们?** 能 = 真 bento。不能(全是大同小异的图标卡)= 假 bento,退回去重做。

## 3. 内容出血 / 重叠(bleed / overlap)

### 构思
别把所有东西关在盒子里。让元素**冲出边界**——截图从右边缘出血、巨大数字重叠到标签上、文字压在图片上。**没有卡片边框,内容直接浮在画布上。** 出血和重叠制造视觉能量,是顶级品牌页的常用手法。

### ASCII
```
┌──────────────────────────────────────┐
│                          ┌───────────┘
│  99.9%                   │
│   (巨大数字,             │   产品截图
│    出血到右侧,            │   (从右边缘
│    重叠到下面的标签)       │    出血,
│   ── uptime              │    无边框)
│      this quarter        │
│                          ↘
└───────────────────────────
```

### CSS
```css
/* 全宽出血图(突破容器到视口边) */
.full-bleed { width: 100vw; margin-left: calc(50% - 50vw); }

/* 巨大数字重叠标签 */
.stat { position: relative; }
.stat .number { font-size: clamp(4rem, 12vw, 10rem); font-weight: 600; line-height: 0.9; letter-spacing: -0.04em; }
.stat .label { position: absolute; bottom: -8px; right: 0; } /* 重叠 */

/* 文字压图 */
.overlay-text { position: absolute; inset: auto 0 0 0; padding: 24px; color: #fff; }
```

### 何时用
hero 数据展示、品牌高光时刻、任何你想注入能量/动感的段落。

### 它凭什么比卡片平铺高级
卡片平铺用边框把内容**关起来**;出血让内容**占据画布**。出血 + 重叠打破"网格里的盒子"的安全感,制造不对称张力和视觉层次。它读作"有构图意图",不是"填格子"。

## 4. 杂志式构图(借一百年排版智慧)

### 构思
杂志花了一百年解决"怎么把混合内容排得好看"——答案从来不是等宽盒子,而是**大图 + 偏移文字栏 + 章节号 + dek(导语)+ 双栏正文**。把这套搬上 web,瞬间脱离 SaaS 卡片气质。

### ASCII
```
┌──────────────────────────────────────────┐
│  ┌──────────────┐                         │
│  │              │   03 ── FEATURES        │
│  │              │                         │
│  │   大图 / 插画 │   大标题(衬线 display)  │
│  │   (左,大)    │                         │
│  │              │   导语 dek(次级)        │
│  │              │                         │
│  └──────────────┘   ┌─────────┬─────────┐ │
│  图注(caption,小)    │ 正文双栏 │ 正文双栏 │ │
│                     │ 排列...  │ 排列... │ │
│                     └─────────┴─────────┘ │
└──────────────────────────────────────────┘
```

### CSS
```css
.magazine { display: grid; grid-template-columns: 5fr 7fr; gap: 48px; align-items: start; }
.magazine .image { /* 大图,左 */ }
.magazine .text  { padding-top: 40px; }           /* 文字栏顶部偏移,不与大图顶对齐 */
.magazine .body  { column-count: 2; column-gap: 32px; }  /* 双栏正文 */
.magazine .section-no { font-family: mono; letter-spacing: 0.1em; color: var(--text-tertiary); }
```

### 何时用
编辑型段落、品牌叙事、想要"出版物"气质的 section(尤其配合衬线 display 字体,见 `visual-language/style-notion.md`)。

### 它凭什么比卡片平铺高级
杂志构图用**尺寸、偏移、字体层级、双栏密度**组织混合内容;卡片平铺用等宽盒子把所有内容压平。一个是排版,一个是填表。

## 5. 高密度数据布局(Linear 式:"每个元素都挣得自己的位置")

### 构思
Linear 的反塑料信条是"**每个元素都挣得自己的位置**"(every element earns its place)。当你的"功能"其实是**带真实数据的能力**时,别做稀疏卡片——做**密集信息列表**,每行是一个能力 + 它的真实指标,扫一眼就懂,每像素都承载信息,**没有一个图标圆圈**。

### ASCII
```
┌──────────────────────────────────────────────┐
│ ● Cycles      weekly cadence · auto-rollover │
│ ● Roadmap     timeline · 4 projects synced   │
│ ● Projects    12 active · 3 archived          │
│ ● Trips       keyboard nav · ⌘K everywhere   │
│ ● Insights    velocity · scope creep alerts  │
└──────────────────────────────────────────────┘
```
每行:**一个色点/标记 + 能力名(加粗)+ 真实数据/指标(次级灰)**。没有图标圆圈,没有等宽卡片,没有 lorem 描述——全是真实信息,密集、可扫。

### CSS
```css
.density-list { display: grid; gap: 0; border-top: 1px solid var(--border); }
.density-row {
  display: grid; grid-template-columns: auto 1fr auto;
  align-items: baseline; gap: 16px;
  padding: 14px 0; border-bottom: 1px solid var(--border);
}
.density-row .name { font-weight: 590; }
.density-row .metric { color: var(--text-tertiary); font-size: 0.9em; }
.density-row .dot { width: 6px; height: 6px; border-radius: 50%; background: var(--accent); }
```

### 何时用
你的 feature 实际是**带数据的工具能力**(开发工具、SaaS、产品页)。当你能填进真实指标时,就别用图标卡。

### 它凭什么比卡片平铺高级
卡片平铺**把空间浪费在装饰上**(图标、padding、等高);高密度布局**把空间全用在信息上**。它读作"做这页的人真的懂自己的产品,知道每个功能值多少"。图标卡读作"做这页的人只有 6 个名词和 6 个图标"。

## 6. 打破对称:内容偏左 + 视觉出血偏右(顶级网页的招牌构图)

### 构思
这是 Linear / Vercel / Stripe 首页的招牌构图:**文字内容锚定左侧(封顶可读宽度),视觉/截图锚定右侧并出血到边缘**。左右不对称(如文字 5 : 视觉 7),制造张力。**这是取代"居中 hero 三件套"的头号正解。**

### ASCII
```
┌──────────────────────────────────────┐
│                                      │
│  H1 价值主张           ┌─────────────┤
│  (偏左, 封顶 ~520px)    │             │
│  副标                   │  真实产品    │
│  [主CTA] [次CTA]        │  截图/UI     │
│  ● ● ● 客户logo         │  (偏右出血)  │
│                         │             │
│  (左侧留白)              │             │
│                         └─────────────┤
└─────────────────────────────────────────
```

### CSS
```css
.hero {
  display: grid;
  grid-template-columns: 5fr 7fr;   /* 不对称:文字 5 视觉 7 */
  align-items: center;
  gap: 48px;
  min-height: 80vh;
}
.hero-text { max-width: 520px; }     /* 文字封顶可读宽度 */
.hero-visual { justify-self: end; }
.hero-visual img { display: block; width: 100%; height: 100%; object-fit: cover; }
/* 视觉出血到右边缘:容器去掉右 padding,图铺满 */
```

### 何时用
hero section、feature 高光段、任何"信息配视觉"的成对段落。这是 web 最常用的高级构图。

### 它凭什么比卡片平铺高级
居中三件套 + 卡片网格是"对称、居中、平均"——安全但无张力;**偏左内容 + 偏右出血视觉**用不对称制造焦点和纵深。文字有可读宽度,视觉有冲击面积,各得其所。

## 选型决策树(当你面对"要展示一堆东西"时)

```
这堆东西里有明确的主角吗?
├─ 有(1 主角 + N 配角)
│   → 【1 编辑型不对称栅格】主菜大 + 配菜小
│
├─ 没有,但每个侧面值得不同对待(图/数据/图表/引用)
│   → 【2 真 bento】大小对比 + 内容类型对比
│
├─ 它们其实是带真实数据的工具能力
│   → 【5 高密度数据布局】密集列表,每行带指标
│
├─ 是品牌叙事 / 编辑内容,想要出版物质感
│   → 【4 杂志式构图】大图 + 偏移文字栏 + 双栏
│
├─ 是 hero / 信息配视觉,要焦点和纵深
│   → 【6 内容偏左 + 视觉偏右出血】
│
└─ 是数据/品牌高光时刻,要能量
    → 【3 出血 / 重叠】巨大数字 + 出血图
```

**默认答案永远不是"3 列等宽 icon 卡片"。** 如果你的第一反应是卡片网格,回到决策树重选。

## 图标圆圈的替代处理(干掉最响的 tell)

卡片平铺最响的 tell 是**彩色圆角方块包 lucide 图标**。替代:

| 塑料(图标圆圈) | 高级替代 |
|---------------|---------|
| ⚡ 在彩色圆角方块里 | **不要图标**——用真实产品截图代替 |
| 🔒 在彩色圆角方块里 | 图标**内联在标题左侧**(16px,无背景方块,继承文字色) |
| 🚀 在彩色圆角方块里 | 用**状态点(6px 色点)** 代替图标(见高密度布局) |
| 每张卡都一个图标 | **整组只用 0-1 个图标**,其余靠版式区分 |

> **铁律:能用截图就不用图标,能用色点就不用图标圆圈,能不放图标就不放。** 图标圆圈是"我不知道这功能长什么样所以画个图标占位"的信号;真实截图是"我懂这功能,这是它的样子"的信号。

## 反塑料证据(feature 区不平铺的"人做的"信号)

- [ ] feature/能力区**不是** 3 列等宽 icon 卡片网格
- [ ] 每个元素**尺寸不同**(有 lead 主菜 / bento 大小对比 / 偏移)
- [ ] **没有**彩色圆角方块包 lucide 图标的重复 motif(用截图/色点/内联图标替代)
- [ ] 内容有**真实数据/截图/图表**,不是 lorem 式描述
- [ ] 至少一处**不对称/出血/重叠**(打破对称网格)
- [ ] 遮住标题,仍能靠尺寸 + 内容类型区分各块
- [ ] 整组用了上面 6 套布局系统之一(或组合),不是默认卡片

## 常见塌方表

| 塌成什么 | 病因 | 修复 |
|---------|------|------|
| feature 区一眼 AI | 3 列等宽 icon 卡 | 换 6 套布局之一 |
| bento 还是塑料 | 格子尺寸略不同但内容类型一样 | 每格换内容类型(图/数据/图表/引用) |
| 每张卡都一个图标圆圈 | lucide-in-rounded-square 重复 | 改截图/色点/内联图标/去图标 |
| 六张卡记不住区别 | 等权无层级 | 给一个 lead 主菜 + 配菜 |
| 看起来"安全但无聊" | 全对称居中 | 加不对称 / 偏左内容 + 偏右出血 |
| 描述全是空话 | 没有"挣得自己位置"的真实信息 | 填真实数据/指标(高密度布局) |

---

## 一句话总纲

> 卡片平铺是"我有 N 个东西所以做了 N 个盒子"。顶级布局是"**每个东西该多大就多大,该是什么就是什么**"。前者是填表,后者是排版。web-craft 的全部努力,就是让 AI 从填表变成排版。
