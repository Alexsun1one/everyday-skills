# 01 — 网页原型库(超越 SaaS dashboard)

> AI 生成"网页"的第一个塌方点:**它不知道自己在做哪种网页**。一个落地页、一个品牌官网、一篇编辑长文、一个商品页——它们的"活"完全不同,动线、节奏、构图纪律完全不同。AI 用同一套"居中 hero + 卡片网格 + 渐入"套所有页,于是全塑料。本文件给 7 种网页原型,每种锁定它的"活 + 动线 + 反塑料铁律",让生成有原型可依。

## 速查:7 种原型一图看清

| 原型 | 这页的"活" | 第一屏必须回答 | 核心纪律 | 锚点站点 |
|------|-----------|--------------|---------|---------|
| **Landing 落地页** | 把路过的人变成点 CTA 的人 | 这是什么 / 给谁 / 为什么现在 | 一屏一主 CTA;feature 不平铺 | linear.app / vercel.com / stripe.com |
| **Brand 品牌官网** | 传达气质,不是卖功能 | 这家是什么人、信什么 | 留白是主角;字体是签名;无转化压力 | family.co / thebrowser.company |
| **Editorial 编辑长文** | 让人读完一篇文章 | 这篇值不值得我 8 分钟 | 窄列阅读流;动效极克制 | press.stripe.com / 杂志长报道 |
| **Portfolio 作品集** | 30 秒判断有水平 | 这人/这家会做什么 | 少而精;大图不对称;不平铺 | 个人/工作室作品站 |
| **Docs 文档站** | 快速找到答案 | 我的问题在哪答了 | 三栏导航;搜索优先;不营销 | stripe.com/docs / vercel.com/docs |
| **Pricing 定价页** | 选对档位并点 CTA | 哪档适合我、值不值 | 对比表 > 卡片;FAQ 兜底 | linear.app/pricing / vercel.com/pricing |
| **Product 电商商品页** | 加购物车 | 这东西长啥样、多少钱、能买吗 | 图是 P0;buy box 一屏可见;无位移 | Apple 产品页 / 电商详情 |

## 1. Landing 落地页

### 这页的活
**把"路过的人"变成"点 CTA 的人"。** 用户从广告/分享链接进来,注意力只有 3-5 秒。首屏必须在用户决定关掉之前回答三件事:**这是什么 / 给谁用 / 为什么现在用**。整页围绕一个转化目标(注册 / 试用 / 下载 / 联系销售)编排。

### 动线(进入 → 出口)
```
进入(3 秒生死线)
 → 首屏 Hero:价值主张 + 一个主 CTA + 信任信号(客户 logo / 数据)
 → 滚动第 1 拍:核心能力(feature,2-4 个,不平铺,见 06)
 → 滚动第 2 拍:具体怎么用(how it works,3 步流程,不是卡片)
 → 滚动第 3 拍:证据(testimonial / 真实数据 / 案例)
 → 滚动第 4 拍:定价锚(一句话指向定价页,或本页简易档位)
 → 终极 CTA band(整宽,一句话 + 主按钮)
 → 页脚(导航 / 合规 / 社交)
出口:用户点 CTA / 跳定价 / 跳文档
```

### 必备 section 清单
`Hero` / `信任带(logo wall 5-6 个真实客户)` / `Feature(2-4 个,不对称,见 06)` / `How it works(3 步)` / `Social proof(testimonial / 数据)` / `Pricing 锚 / CTA band` / `Footer`。

### 信息层级
1. H1 价值主张(最大,weight 600-700)
2. 副标(一句解释,weight 400,对比度低一档)
3. 主 CTA(唯一视觉权重最高的可点元素)
4. 信任信号(客户 logo / "被 X 个团队使用")
5. 其余全部更低权重

### 该原型独有反塑料铁律
1. **Hero 不许居中三件套 + 彩色 blob。** AI 默认 hero = 居中大标题 + 渐变文字 + 居中双 CTA + 下面产品截图漂在紫粉渐变 blob 上。这是 2023-2026 最浓塑料味。正解:文字**偏左** + 真实产品截图/UI **偏右出血**(或一个强视觉占满),形成不对称张力。
2. **Logo wall 顶多 5-6 个,且必须真相关。** AI 爱堆 12 个灰度 logo 假装"被信任"——读起来就是假的。5-6 个行业相关、真实的客户 logo > 12 个不相关的灰块。
3. **一屏一个 CTA 占绝对最高视觉权重。** 下一屏才换 CTA 形态。Hero 里出现两个等权 CTA(如 "Get started" + "Talk to sales")时,主次必须拉开:主 CTA 实心 accent,次 CTA ghost 文字链接,不能两个都实心。
4. **How it works 是流程不是卡片。** 3 步用编号 + 箭头 + 截图横排/纵排,**不是 3 张等宽 icon 卡**。

### AI 最爱犯的错
居中 hero + 渐变大字 + 下方 6 张等宽 lucide 卡片 + 全页 fade-in-up。**这一套几乎等于在标题写"AI 生成"**。改法见 `06-anti-card-tiling.md` 和 `03-scroll-storytelling.md`。

## 2. Brand 品牌官网

### 这页的活
**不是卖功能,是传达"这家公司是什么人、什么气质、信什么"。** 转化是次要的(甚至没有强 CTA)。气质是唯一的交付物。看的人是潜在用户、潜在员工、媒体、投资人——他们来"感受",不是来"下单"。

### 动线
```
进入(第一眼定生死)
 → Hero:一句品牌主张,大字,留白极多,通常一张极简视觉或纯字
 → Manifesto / Philosophy:我们信什么(大段排版,呼吸感)
 → 视觉语言展示:产品哲学、设计系统、工艺(图片/视频叙事)
 → Selected work / 案例:艺术性排版,不平铺
 → Values / Team / 加入我们
 → 极简页脚(大量留白)
出口:用户记住气质 / 点 Contact / 看 work
```

### 必备 section 清单
`Hero(大字宣言)` / `Manifesto 或 philosophy` / `视觉系统/工艺展示` / `Selected work(艺术排版)` / `Values / Team` / `Contact / Join` / `极简 Footer`。

### 信息层级
1. 品牌主张(超大字,常占满首屏一半高度)
2. 留白(和文字同级,是构图元素不是空气)
3. 视觉资产(大图/视频,出血)
4. 正文 philosophy(weight 300-400,大 line-height)

### 该原型独有反塑料铁律
1. **留白是主角,不是空气。** 品牌页 section 间距 **120-200px+**,比落地页(40-80px)大 2-3 倍。空本身就是气质。把品牌页 section 间距做成落地页的密度 = 把品牌页做废了。
2. **字体是签名。** 必须用一套有性格的字体组合:衬线 display + sans 正文,或 grotesk + mono,或定制字体。**Inter 单字族打天下 = 通用 SaaS,不是品牌。** 字体选择本身就是品牌主张。
3. **不放价格、不放功能对比表、不放"为什么选我们"。** 那是落地页和定价页的活。品牌页堆这些 = 降级成落地页,丢失气质。
4. **CTA 极克制。** 最多一个 "Get in touch" 文字链接。品牌页没有转化焦虑,不该有多个实心 CTA 施压。

### AI 最爱犯的错
把品牌页做成"带 logo 的落地页"(堆 feature 卡 + 多个 CTA + 定价)。AI 不适应"没有转化目标"的页,于是乱塞营销元素。**品牌页的核心判断是"砍什么":砍掉一切营销压力,只留气质。**

## 3. Editorial 编辑型长文

### 这页的活
**让人读完一篇文章/报道/深度分析。** 可读性是唯一指标。用户已经决定要读,你的活是**别让他中途放弃**。

### 动线
```
进入
 → 文章头:大标题 + dek(副标/导语)+ 作者 + 时间 + 阅读时长
 → (sticky)阅读进度条 + 章节锚点目录
 → 正文:单栏窄列(60-75 字符/行),固定居中
 → 穿插:pull quote(大引用)/ 图片+图注 / 数据可视化 / 代码
 → 文末:作者卡片 + 相关阅读 + (可选)评论
出口:读完 / 跳相关
```

### 必备 section 清单
`Article header(标题+dek+作者元信息)` / `阅读进度条(sticky)` / `TOC(sticky 或 inline)` / `正文窄列` / `Pull quotes` / `图片 + 图注` / `文末作者卡 + 相关阅读`。

### 信息层级
1. 文章标题(display 字号,weight 600-700,但 line-height 紧 1.1-1.15)
2. 正文(主角,weight 400,line-height 1.6-1.75)
3. 小标题 H2/H3(章节锚点)
4. 图注(weight 300,小字,灰)
5. 元信息(作者/时间,最小)

### 该原型独有反塑料铁律
1. **正文列宽 60-75 字符(中文 30-40 字),硬科学。** 这是眼动研究确认的最佳阅读宽度。宽了视线跳行丢字,窄了像手机列。容器 `max-width: 65ch`(英文)/ 中文用 `max-width: 42em` 左右。
2. **line-height 1.6-1.75(正文)。** 段间距 = 行高的 1.5-2x。CJK 字符比拉丁字"重",line-height 给到 1.75-1.85 更舒服(见 visual-language/style-chinese-saas.md 的 CJK breathing)。
3. **动效极克制。** 最多一个阅读进度条 + 当前章节锚点高亮。**正文段落不要 fade-in**——会打断阅读节奏。编辑型页的动效纪律是"几乎不动"。
4. **图注必须有,且与正文区分层级。** AI 常丢图注或把图注做成正文同字号。图注是 weight 300、小一号、灰、居中或左对齐——它是"解释图的",不是正文。

### AI 最爱犯的错
把长文做成"每个 H2 一张配图卡片"的图文卡片集。**编辑型长文是文字密度页,卡片化会把它撕碎。** 也爱把正文列做太宽(占满 1200px)导致跳行。

## 4. Portfolio 作品集

### 这页的活
**让看的人(招聘方/客户)在 30 秒内判断"这人/这家有水平"。** 质量 > 数量,留白 > 装饰。第一眼就定调。

### 动线
```
进入
 → Intro:名字 + 一句定位(极简,大量留白)
 → Selected work:3-6 个精选作品,大图,不对称(见 06)
 → (点进单个)Case study:项目背景 / 我的角色 / 过程 / 结果(大图叙事)
 → About:能力 / 经历(克制)
 → Contact:一个联系方式,不堆
出口:看作品 / 点 contact
```

### 必备 section 清单
`Intro(名字+定位)` / `Selected work(大图不对称)` / `Case studies(可展开)` / `About` / `Contact`。

### 信息层级
1. 作品大图(主角,占视觉面积最大)
2. 作品标题 + 一句描述(weight 400-500)
3. 作品元信息(年份/角色/类型,weight 300,小字)
4. 个人定位(首屏,但不抢作品)

### 该原型独有反塑料铁律
1. **作品少而精。** 3-6 个精选 > 20 个网格。每个作品给足空间(整宽或半宽大图 + 留白)。**展示 6 个顶级作品 > 展示 20 个平庸作品**——后者暴露你没东西可选。
2. **作品图必须真实、高质量、大尺寸。** 占位图 / 低分辨率 / 截图带浏览器 chrome 全 = 业余信号。作品图是这页的产品本身。
3. **不对称构图。** 大作品图偏右出血 + 左侧留白 + 标题元信息偏左。**绝不等宽缩略图网格**(那是 Pinterest,不是作品集)。具体手法见 `06-anti-card-tiling.md`。

### AI 最爱犯的错
做成"9 宫格/12 宫格缩略图墙 + 点击放大"。缩略图墙把每个作品压成等大的方块,抹平了质量差异,看不出"哪个是代表作"。正解是**主次分明的不对称大图叙事**。

## 5. Docs 文档站

### 这页的活
**让开发者/用户快速找到并理解答案。** 搜索 + 导航 + 可读性 >> 好看。用户来这是"带着问题来的",你的活是**让他 30 秒内找到答案、看完就走**。

### 动线
```
进入(带着问题)
 → 顶部:logo + 全局搜索(⌘K,主角)+ 版本切换 + 主题切换
 → 左栏:目录树(sticky,可折叠,高亮当前页)
 → 中栏:正文(标题 + 正文 + 代码块 + 提示框),锚点
 → 右栏:本页大纲 On this page(sticky,滚动高亮当前节)
 → 底部:上一篇 / 下一篇 + "编辑此页"
出口:找到答案关掉
```

### 必备 section 清单
`Top bar(logo + 搜索 + 版本 + 主题)` / `左侧导航树(sticky)` / `正文(标题+正文+代码+callout)` / `右侧 On this page(sticky)` / `底部 prev/next + edit`。

### 信息层级
1. **搜索框**(docs 用户的第一动作,视觉上要显眼)
2. 当前页标题(正文区顶部)
3. 正文 + 代码块(主角)
4. 左右两栏导航(辅助,sticky)

### 该原型独有反塑料铁律
1. **三栏是默认,移动端折叠成单栏 + 抽屉目录。** 不要在文档站玩不对称构图或品牌叙事——可读性和可导航性绝对优先。Stripe / Vercel / Linear docs 都是三栏,是有原因的。
2. **代码块必须有:语言标签 + 复制按钮 + (长代码)行号 + 语法高亮。** 这是开发者信任信号。没有复制按钮的代码块 = 不懂开发者。
3. **正文纪律与编辑长文同(窄列、line-height 1.65),但可更宽。** 因为左目录占位,中栏正文通常 700-820px。code 可适当更宽或 full-bleed。
4. **第一屏是搜索 + 目录,不是营销 hero。** AI 爱给文档站加一个大渐变 hero——docs 用户不需要被营销,他需要找答案。

### AI 最爱犯的错
把文档站做得"很营销"(大 hero、渐变、feature 卡)。文档站的成功指标是"用户最快离开",不是"用户多停留"。

## 6. Pricing 定价页

### 这页的活
**让用户选对档位并点 CTA。** 可比性 + 降低决策焦虑是核心。用户已经心动,在比价,你的活是**让他不焦虑地做决定**。

### 动线
```
进入
 → 一句话定位 + 计费切换(月付/年付,toggle)
 → 价格卡:2-4 档(推荐档高亮)
 → 对比表:feature 矩阵(行=功能,列=档位,勾/叉)
 → FAQ:回答"我该选哪档""能换吗""超额怎么算"
 → 底部 CTA band / 联系销售
出口:点档位 CTA / 联系销售
```

### 必备 section 清单
`Header + billing toggle` / `Pricing cards(突出推荐档)` / `Feature comparison table` / `FAQ` / `CTA band`。

### 信息层级
1. 推荐档位(视觉上突出:边框/scale/"Most popular" badge)
2. 每档价格(大数字,小单位)
3. 每档 CTA
4. 对比表(决策依据)
5. FAQ(兜底焦虑)

### 该原型独有反塑料铁律
1. **对比表 > 价格卡。** 价格卡给概览,但真正决策靠对比表。**AI 爱只做卡片、不做表——这是定价页最大塑料。** 没有对比表的定价页,用户无法判断"多花的钱买到什么",于是弃单。
2. **推荐档高亮,但不降其他档透明度。** 用 scale 1.02 + accent 边框 + badge 突出推荐档。**不要把非推荐档做成 opacity 0.5**——那看起来像在操纵用户,反而不信任。
3. **价格数字大、单位小。** `$29` 大号 weight 600,`/mo` 小号 weight 400 灰色。计费切换(月/年)必须**即时更新价格**(乐观更新,不等请求)。
4. **FAQ 必须回答真实决策焦虑**,不是凑数。"我能随时换档吗""超额怎么算""团队版最少几人"——这些是用户真问的。"我们性价比最高"这种不是 FAQ,是营销。

### AI 最爱犯的错
三张等宽价格卡 + 中间一张高亮 + 没有对比表 + FAQ 全是"为什么选我们"。正解:卡片 + **对比表** + FAQ 兜底真实焦虑。

## 7. Product 电商商品详情页

### 这页的活
**让用户加购物车。** 图片说服力 + 关键信息(价格/规格/库存/运费)+ 信任(评价/退换)是转化三件套。

### 动线
```
进入
 → 左:图集(主图大 + 缩略图,sticky 跟随滚动)
 → 右:buy box —— 标题 / 价格 / 评分 / 变体选择(color/size)/ 数量 / 主 CTA 加购 / 信任徽章(运费/退换/支付)
 → 往下:详情描述 / 规格表 / 评价 / 相关推荐
出口:加购 / 立即购买
```

### 必备 section 清单
`Gallery(sticky 图集)` / `Buy box(标题+价格+变体+数量+CTA)` / `信任带(运费/退换/支付)` / `描述` / `Specs 规格表` / `Reviews 评价` / `Related 相关推荐`。

### 信息层级
1. **图片**(P0,占左半屏,sticky)
2. 标题 + 价格(buy box 顶部)
3. 主 CTA"加入购物车"(buy box 内,视觉最强)
4. 变体选择 / 数量(CTA 上方)
5. 信任徽章 / 评分(辅助)

### 该原型独有反塑料铁律
1. **图片是 P0。** 主图大、清晰、可点击放大、有多角度(正面/侧面/细节/场景)。图片加载**不能让 buy box 位移**(CLS,见 `05-performance-as-design.md`)——图位必须预留固定 aspect-ratio。
2. **Buy box 信息一屏可见。** 标题 + 价格 + 变体 + 数量 + CTA 在桌面端不滚动就能看到全。变体选择(color/size)**就近 CTA**,不要分屏。
3. **评价用真实结构**:星级 + 评价数量 + 少量真实文字摘录 + 优缺点标签。不要"⭐⭐⭐⭐⭐ 完美!"五条假五星——一眼假。
4. **"加入购物车"是主 CTA。** "立即购买"次级或并列。不要两个实心等权按钮(违反"一屏一主 CTA")。

### AI 最爱犯的错
把商品页做成营销页(顶部大品牌 hero banner)。商品页第一屏是"图片 + 购买信息",不是品牌宣传。用户已经知道要买什么,不需要被重新营销。

## 原型选型决策树

```
用户要"网页",问第一个问题:这页的活是什么?
├─ 卖功能/拉注册/拉下载         → Landing
├─ 传达气质/招人/品牌形象        → Brand
├─ 让人读完一篇文章              → Editorial
├─ 展示作品/能力(给招聘方/客户) → Portfolio
├─ 查文档/找答案                → Docs
├─ 比价/选档位                  → Pricing
└─ 卖具体商品/下单              → Product

混合型:
├─ "Apple 式产品发布页" = Brand 气质 + Landing 转化 + 滚动叙事(见 03)
├─ "SaaS 官网首页"     = Landing(主)+ 链接到 Docs/Pricing
└─ "个人网站"          = Portfolio + Brand 混合
```

## 跨原型通用铁律(所有网页原型都守)

1. **第一屏 3 秒内传达价值主张**——除了 Docs(Editorial/Brand 可慢一点,Docs 是带着问题来的)。
2. **一屏一个主 CTA 最高视觉权重**——除了 Brand(无 CTA 压力)和 Editorial(无 CTA)。
3. **feature/能力区不平铺卡片**——见 `06-anti-card-tiling.md`,所有原型都适用。
4. **动效克制 + 可打断 + reduced-motion**——见 `02-motion-system.md`。
5. **响应式是每断点重新构图,不是等比缩小**——见 `04-responsive-art-direction.md`。

> 选错原型 = 全盘错。一个被当成 Landing 做的 Brand 页(堆 CTA),或被当成 Portfolio 做的 Docs(缩略图墙),无论像素多精确都塑料——因为动线和纪律错了。先定原型,再画线稿。
