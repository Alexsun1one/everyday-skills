# AI Self-Review Loop — 生成中自审提示词（不是验收提示词）

> 出处:原文行 906-935。原文金句:**"大模型不怕返工,人怕。利用这一点,让它写完先别交,自己切换成一位苛刻的产品设计评审,逐条挑刺。"**

## 这不是 qa-*，是生成 loop 的第二步

| 维度 | qa-*.md(验收层) | 本文件(生成 loop) |
|---|---|---|
| 何时跑 | **交付前**——产物已经生成完,验收员按清单查 | **生成中**——刚写完第一稿,立刻自审,再改 |
| 谁来跑 | Agent 自检 + 人工把关 | 同一个 Agent 切换角色,**自己挑自己的刺** |
| 输出去向 | P0/P1/P2 分级表,人决策修不修 | 修改后的最终版本,直接进交付 |
| 目标 | 拦住烂产物,不准 ship | 在交付前把 AI 味按在地上 |

**两者正交,不能互替**:qa-* 是产物层 gate,本文件是生成层 loop。理想流程是 Agent 生成 → 自审 loop(本文) → qa-* 验收(交付前) → 人工把关 → ship。

## 自审 loop 的核心机制：角色切换

> 原文行 913-929 verbatim。Agent 写完第一稿后,**强制切换角色**——从"运动员"切到"裁判",不许夸自己。

```text
自审 loop 提示词（写完第一稿后立刻跑）:

现在请你切换成一位苛刻的产品设计评审。
不要夸自己刚才的输出,不要说"以上设计已经很好"之类的话。

请逐条检查:

1. 有没有空话套话?
   （"高级感"、"现代感"、"用户友好"、"清晰直观"——这些是空话,
   说不出具体数值/具体状态/具体场景的都是空话）

2. 有没有"没有数值的规范"?
   （"间距合理"是空话;"间距 4/8 网格,卡片 padding 24px,卡间 16px"是规范）

3. 有没有组件只写了默认态?
   （按钮只写了 default 是不合格;必须覆盖 8 态 default/hover/active/focus/disabled/loading/success/error）

4. 有没有漏掉 loading / empty / error / permission denied / offline 状态?
   （每个数据模块必须覆盖这 5 态,缺一不可）

5. 有没有违反"一屏一个主按钮"?
   （一屏出现 2 个 primary 按钮 = IA 错了,先修 IA）

6. 有没有把复杂任务塞进模态?
   （复杂多步任务用抽屉/独立页,模态只用于硬中断/简单确认）

7. 有没有直接写死颜色值,而不是使用语义令牌?
   （任何 #5E6AD2 写在组件里都是不合格;必须 color.primary / color.action 语义层）

8. 有没有缺少可访问性和键盘操作要求?
   （focus ring 不能删、icon button 必须 aria-label、模态必须 focus trap）

请输出:
- 问题列表（按上面 8 条编号,逐条答"有/没有"）
- 为什么是问题（引用刚才输出的具体段落）
- 应该怎么改（可执行的修正方向）
- 修改后的最终版本（不是"建议修改",是直接给改好的版本）
```

## 执行纪律

1. **写完第一稿立刻跑**,不要等用户发现。原文行 929:"**先让 AI 自己挑刺,再交给人。**"
2. **角色切换必须明确**——"现在请你切换成一位苛刻的产品设计评审"。模糊的角色切换(如"再看看有没有问题")会让 Agent 倾向于自我安慰。
3. **8 项检查必须逐条答**,不能合并成"以上都没问题"。合并=走过场。
4. **第四段"修改后的最终版本"必须给**——没有这一段等于没改,只是诊断。
5. **不要和 qa-* 串行误用**——qa-* 是交付前 gate,本文是生成中 loop。混用会让 Agent 跑两次相似但不相同的检查,浪费时间且互相覆盖。

## 反模式

| 反模式 | 为什么坏 | 修正 |
|---|---|---|
| 写完第一稿直接交付 | AI 第一稿必然有 8 项中至少 2-3 项违 | 强制跑自审 loop |
| 跑自审但不切换角色 | Agent 倾向于"我刚才写得挺好" | 明确"切换成苛刻评审,不要夸自己" |
| 8 项合并答"全部合格" | 走过场 | 强制逐条答"有/没有" |
| 只输出诊断,不输出修改版本 | 等于只挑刺不修 | 第四段"修改后版本"必须给 |
| 把自审 loop 当 qa-* 跑 | 混淆生成层和验收层 | 自审是生成 loop 的一部分,qa-* 是交付 gate |

## 在 skill pipeline 里的位置

```
Intent Brief
   ↓
Anti-Plastic Test
   ↓
Stage 0 判断卡（5 张）
   ↓
Stage 1 五层切片草稿
   ↓
[这里] → 第一稿完成 → 跑自审 loop（本文件）→ 修改后版本
   ↓
Stage 2 高保真还原
   ↓
qa-p0p1p2 / qa-page-five-questions / qa-state-acceptance / qa-a11y / qa-responsive / qa-bad-data（交付前 gate）
   ↓
qa-polish（打磨,过 gate 才能进）
   ↓
人工走关键路径 → ship
```

自审 loop 在 Stage 1 第一稿之后、Stage 2 之前。它的目标是让 Stage 2 拿到的草稿已经过了 8 项自检,不是 Stage 2 还在补 Stage 1 的洞。

## 与 qa-* 的边界（再次强调）

- **自审 loop**:生成中,Agent 自己挑自己的刺,目标是改进第一稿,输出"修改后版本"
- **qa-***:交付前,Agent 按清单验收,目标是拦截烂产物,输出 P0/P1/P2 分级

混淆的后果:Agent 把自审 loop 当 qa-* 跑,只输出诊断不给修改版本;或把 qa-* 当自审 loop 跑,在生成中就开始分级,打断创造流程。**两者必须分开。**
