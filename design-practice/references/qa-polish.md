# QA Polish — 世界级打磨清单

> 出处:原文行 1844-1864。这是 P0/P1/P2 验收**之后**的独立阶段,不是 P2 的一部分。
>
> 原文金句(行 1846):**"一个页面如果提交失败会丢内容,动效再柔也没用。"** —— 顺序纪律:先把产品从"不可靠"做到"可靠",再从"可靠"做到"顺",最后从"顺"做到"有气质"。**不要跳级。**

## 进入打磨阶段的前置 gate（硬顺序）

**没有全过不准打磨——那是给烂流程化妆。** 必须先全部通过的检查项:

```text
□ P0 全过(主任务走通 / 无重复提交风险 / 失败保内容 / 权限矩阵全过 / 错误就地 / 状态全覆盖 / 边界数据不崩 / 离线不假成功)
□ P1 全过(8 态 / focus ring / focus trap / aria / token / 响应式 / 深色 / reduced-motion / 文案具体 / 字阶一致 / 4-8 网格 / 一屏一主按钮)
□ 页面五问全过(我是谁 / 给谁看 / 干什么 / 下一步 / 不能做时怎么办)
□ 状态验收全过(qa-state-acceptance)
□ a11y 验收全过(qa-a11y)
□ 响应式验收全过(qa-responsive)
□ 坏数据验收全过(qa-bad-data)
```

任何一项没过 → 回去修,不准进入打磨。**打磨不能掩盖可靠性问题。**

## 世界级打磨的 7 项（原文行 1848-1862 verbatim）

| # | 维度 | 塑料样 | 世界级样 | 怎么打磨 |
|---|---|---|---|---|
| 1 | **微文案** | 系统日志式（"操作失败"、"请求错误"） | 人话（"网络断了,你的修改还在,再点一次就好"） | 每条 toast / error / empty 文案过一遍,问"用户读完知道下一步该干嘛吗" |
| 2 | **动效** | 长(>500ms) / 线性 / 无空间逻辑 | 短(150-300ms) / 自然曲线 / 表达空间关系(列表→详情从父元素长出) | 每个转场问"它告诉用户从哪来、到哪去了吗" |
| 3 | **空状态** | "暂无数据" | 有指导性(说明为什么空 + 下一步行动) | 三种空(initial / filter / permission)各有专属文案 + CTA |
| 4 | **表格密度** | 默认行高,所有列同宽 | 行高紧凑(40-48px),关键列宽,辅助列窄 | 按扫读速度调,5 秒应能扫完 20 行 |
| 5 | **关键数字 vs 辅助信息** | 所有数字同样大、同样字重 | 关键数字大、字重 600;辅助信息小、字重 400、浅灰 | 找出每屏的"用户最关心的 1-3 个数字",其余降级 |
| 6 | **成功 vs 危险反馈** | 成功和危险同样重(都大红大绿) | 成功反馈克制(200ms 闪烁、轻 toast)、危险反馈慎重(红色 banner + 需确认) | 成功不让用户停,危险让用户停 |
| 7 | **页面节奏** | 所有区块同样大、同样间距 | 有节奏(大区-小区-大区),眼睛知道何时喘气 | 间距分级(8/16/24/32),不要全用 16px |

## 四层进阶（原文行 1862-1864）

> 原文金句:"先把产品从'不可靠'做到'可靠',再从'可靠'做到'顺',最后从'顺'做到'有气质'。**不要跳级。**"

```
不可靠  →  可靠  →  顺  →  有气质
  ↑         ↑       ↑        ↑
 P0 修    P1 修    P2 修    打磨
```

| 层级 | 状态 | 用户感受 | 阶段 |
|---|---|---|---|
| 1 不可靠 | 主任务走不通 / 数据丢 / 状态漏 | "这产品坏了" | P0 修之前 |
| 2 可靠 | 主任务能走通,但卡顿 / 文案奇怪 / 反馈不明确 | "能用但烦" | P0 修完,P1 修中 |
| 3 顺 | 主任务流畅,反馈明确,文案说人话 | "用着舒服" | P1 修完,P2 修中 |
| 4 有气质 | 有微妙的细节(动效自然 / 节奏舒服 / 危险慎重 / 成功克制) | "这产品懂我" | 打磨之后 |

**跳级的反例**:产品还在"不可靠"(主任务走不通)就开始打磨动效——这是给烂流程化妆。原文反复警告:"动效再柔也没用,因为提交失败会丢内容。"

## 打磨的执行顺序（防止打磨变拖延）

打磨不能无止境。每项打磨必须有"够了"的判定:

```text
打磨顺序(原文隐含 + 实操经验):
1. 微文案 → 每条文案读 3 遍,过了就过
2. 动效 → 每个转场问"表达空间关系了吗",答了就过
3. 空状态 → 三种空都有专属文案 + CTA 就过
4. 表格密度 → 5 秒扫完 20 行就过
5. 关键数字 → 每屏 1-3 个突出数字就过
6. 成功/危险反馈 → 成功 ≤ 200ms 闪、危险有确认就过
7. 页面节奏 → 区块间距分 3 档就过

每项打磨限时 15 分钟,超时进 backlog。
打磨不是无止境精修,是"让 7 项都从塑料样变到世界级样"。
```

## 反模式

| 反模式 | 为什么坏 | 修正 |
|---|---|---|
| 在 P0 没全过时打磨动效 | 动效再柔,主任务失败用户还是用不了 | 先修 P0,过 gate 再打磨 |
| 打磨变精修,一打磨就两周 | 边际效益递减,该 ship 不 ship | 每项限时 15 分钟 |
| 跳过文案打磨只动动效 | 文案是"产品说话的方式",塑料文案 = 塑料产品 | 微文案是打磨第 1 项 |
| 给所有数字加渐变和动画 | 关键数字被淹没,失去对比 | 只给 1-3 个关键数字突出 |
| 成功反馈做得喜庆(烟花、五彩纸屑) | 成功不是表演,是用户的下一步路标 | 成功反馈克制(200ms 闪、轻 toast) |
