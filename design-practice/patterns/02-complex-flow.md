# patterns/02 — 复杂流程设计(向导 / 分支 / 回退 / 草稿)

> 出处:《设计的实践》第 17 章(行 6663–6798,原文 **46 次提及**草稿/回退)
> 严重度:★★★ — 这是 AI 产物最缺的能力,因为 AI 默认只画 happy path

## 一句话

> **复杂流程不是把步骤切碎。真正的复杂流程设计要处理五件事:用户从哪进、每步为什么必要、哪些可跳过、中途失败/返回/退出怎么办、回来后能不能接着做。复杂流程不是"步骤列表",而是有入口、有分支、有回退、有保存、有恢复的道路。**

## 复杂流程的五个核心问题

| 问题 | 必答 | 错误做法 |
|---|---|---|
| **入口** | 用户从哪几种地方进入这个流程? | 只设计一个入口 |
| **必要性** | 每一步为什么必须有?能合并吗?能跳过吗? | 把步骤切碎假装专业 |
| **分支** | 哪些条件会改变后续路径? | 只画直线流程 |
| **回退** | 中途失败、返回、退出怎么办? | 数据全丢,用户从头来 |
| **恢复** | 用户回来能不能接着做? | 没有"草稿",退出即作废 |

## 入口设计(常被忽略)

复杂流程的入口不止一个。同一个"创建订单"流程,可能从:

- 客户详情页(给这个客户下单)
- 产品详情页(买这个产品)
- 主导航"新建"
- 通知"补全信息"
- 移动端"快速创建"
- AI 推荐"基于上下文创建"

**入口不同,流程的默认值、必填项、第一屏都不同**。新手只设计一个入口,所有用户走同样的路。高手根据入口预填,让用户少走路。

## 必要性判断(每步都要问)

每一步都要回答三个问题,否则就是冗余:

```
1. 这一步解决什么具体问题?
2. 没这一步会怎样?
3. 这一步能不能合并、跳过、延后?
```

**真正必要的步骤,通常只有 3–5 步**。如果你的流程有 10 步,大概率 5 步是"看起来专业"的伪必要。

## 分支设计(复杂度的真正来源)

复杂流程不是直线,是带 if-else 的树:

```
第 1 步:选客户类型
   ├── 个人客户 → 第 2a 步(身份证验证)
   ├── 企业客户 → 第 2b 步(营业执照)
   └── 渠道客户 → 第 2c 步(合同上传)

第 2a 步:...
第 2b 步:...        ← 不同分支步骤不同
第 2c 步:...

第 3 步:汇合点(基本信息)
   ↓
第 4 步:...
```

**分支的反模式**:把所有分支的字段都塞进一个表单,让所有用户都填一遍。这是把复杂度甩给用户(参见 [判断卡 1](../design-judgment/02-complexity-conservation.md))。

正确做法:**根据条件显隐字段**,用户只看到自己路径上的字段。

## 回退设计(AI 最容易漏)

**用户中途退出的 5 种情况,每种都要设计**:

| 退出情况 | 系统应该做什么 | 错误做法 |
|---|---|---|
| **主动返回** | 保留已填内容,提示"未保存" | 直接退出,数据全丢 |
| **网络中断** | 本地暂存,恢复后自动同步 | 弹窗报错,用户重填 |
| **关闭浏览器** | 草稿自动保存,下次回来恢复 | 数据丢失 |
| **超时** | 锁定当前状态,登录后继续 | 强制重新开始 |
| **错误中断** | 保留已正确部分,只重试出错步骤 | 整个流程重来 |

## 草稿与恢复(严肃产品的标配)

严肃产品(订单、合同、报销、申请)必须有草稿机制:

```
草稿状态
   ├── 自动保存(每 5s 或字段变化时)
   ├── 手动保存("存草稿"按钮)
   ├── 草稿列表(用户能找到自己的草稿)
   ├── 草稿恢复(回来时弹"继续上次的填写?")
   ├── 草稿过期(7–30 天后清理)
   └── 草稿删除(用户能主动删)
```

**没有草稿 = 这个流程只能一次成功 = 用户出错就流失。**

## 复杂流程的反模式(AI 产物最常犯)

### 反模式 1:直线流程

```
坏的: 步骤 1 → 2 → 3 → 4 → 5 → 完成
     没分支,没回退,没草稿。
病根: 把复杂流程当简单表单做。
```

### 反模式 2:进度条骗人

```
坏的: 进度条显示"第 3/5 步",但实际第 3 步里有 5 个子步骤,
     用户感觉永远走不完。
病根: 进度条没反映真实复杂度。
```

### 反模式 3:必填地狱

```
坏的: 每一步所有字段都必填,用户卡在中间动不了。
病根: 没区分"这一步必须的"和"流程必须的(可延后)"。
```

### 反模式 4:无出口

```
坏的: 用户做到第 4 步发现要个文件没有,只能放弃,数据全没。
病根: 没"保存草稿退出"。
```

### 反模式 5:分支地狱

```
坏的: 把所有分支字段都塞进主流程,用户被无关字段淹没。
病根: 没做条件显隐。
```

## 复杂流程提示词(原文 17 章)

```
你是一位资深产品设计师。请设计一个复杂流程,必须处理入口、分支、
回退、草稿、恢复,不要只画直线 happy path。

流程目标:{创建订单、报销申请、合同审批、入职流程...}
用户角色 + 场景:{谁、什么时候、为什么、出错代价多高}

请输出:

1. 入口设计
   - 用户从哪几种地方进入这个流程(列出 3–6 个入口)
   - 不同入口预填什么、第一屏显示什么

2. 步骤设计
   - 每一步解决什么具体问题(必答)
   - 哪些步骤可合并、跳过、延后
   - 必要步骤的真实数量(应该 3–5 步)

3. 分支设计
   - 用 Mermaid 画分支树
   - 每个分支的触发条件
   - 哪些字段条件显隐

4. 回退设计
   - 5 种退出情况(主动返回/网络中断/关闭浏览器/超时/错误中断)
   - 每种情况系统做什么

5. 草稿与恢复
   - 自动保存策略
   - 草稿列表入口
   - 草稿恢复提示
   - 草稿过期与删除

6. 反模式自查
   - 是不是直线流程?
   - 进度条是否反映真实复杂度?
   - 是否必填地狱?
   - 是否有出口(草稿)?
   - 是否分支地狱(条件显隐没做)?

要求:
- 不要写空话,每步说明必要性
- 用 Mermaid 画流程图,要包含分支和回退路径
- 必须包含至少一个 unhappy path 的处理
```
