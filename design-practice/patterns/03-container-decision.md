# patterns/03 — 容器决策树(页面 / 抽屉 / 模态 / Popover / Toast)

> 出处:《设计的实践》第 15 章(行 6356–6496)
> 严重度:★★ — 跳过它,产物会"什么都用模态"或"什么都整页跳转",交互成本高

## 一句话

> **容器不是装饰,是用户认知的边界。选错容器,用户要么被打断,要么迷路。每个容器有自己的脾气,选错就是失礼。**

## 五种容器对照表

| 容器 | 适合 | 不适合 | 破坏专注 | 保留上下文 |
|---|---|---|---|---|
| **整页** | 主任务流、长内容、可分享 URL | 临时操作、轻量编辑 | 不破坏(本来就在主路径) | 不保留(换了页) |
| **抽屉(Drawer)** | 快速查看、轻量编辑、连续处理多个 | 长内容、必填表单 | 轻微(挡一半) | 保留(列表还在) |
| **模态(Modal)** | 强制决策、短确认、必须完成才能走 | 长表单、多步骤、复杂操作 | 严重(全屏遮挡) | 保留(背后还在) |
| **Popover** | 小调整、补全、提示、菜单选项 | 重要决策、必填项 | 几乎不破坏 | 完全保留 |
| **Toast** | 短反馈、操作确认、撤销入口 | 重要信息、需要操作的内容 | 几乎不破坏 | 完全保留 |

## 容器决策树(原文 15 章核心)

```
用户要做一件事
   │
   ▼
这件事是主任务流的一部分吗?
   │
   ├── 是 ────────────────────────────> 整页
   │                                    (主路径,可分享 URL)
   │
   └── 否,是临时操作 ──┐
                        ▼
              这个操作需要用户专注吗?
                        │
                        ├── 需要强制专注(必答、必确认)──> 模态
                        │                                (全屏,遮罩,必完成)
                        │
                        ├── 需要快速操作,但要看到上下文 ──> 抽屉
                        │                                (右侧滑入,挡一半)
                        │
                        └── 极轻量(菜单、补全、提示)──> Popover
                                                         (浮层,点外部关)
                        
独立于操作之外:
   - 反馈/确认/撤销 ────────────────────> Toast
                                         (短停留,自动消失)
   - 重要通知/系统级提示 ───────────────> Banner
                                         (顶部常驻,可关闭)
```

## 五种容器的"潜规则"

### 整页(Page)

- **URL 必须**:整页必须有独立 URL,可分享、可刷新、可后退。
- **导航交互**:有面包屑、返回按钮、页面标题。
- **慎用**:不要为了"装得多"就把临时操作也做成整页,会打断主任务。

### 抽屉(Drawer)

- **宽度**:桌面端 400–640px,移动端全屏。
- **必须保留上下文**:打开抽屉时背后页面不卸载。
- **关闭**:点遮罩、ESC、返回按钮三种都能关。
- **慎用**:抽屉里别放长表单或多步骤流程,会很憋屈。

### 模态(Modal)

- **宽度**:480–640px,别太宽。
- **强制专注**:打开时背景遮罩,必完成才能走。
- **慎用**:别在模态里放模态(双层),用户会迷路。
- **慎用**:别把多步骤流程塞模态,模态是"短决策"不是"长任务"。

### Popover

- **小而快**:点开即用,用完即关。
- **位置**:跟着触发元素,不挡主视觉。
- **关闭**:点外部、ESC、再次点击触发元素。
- **慎用**:不要在 Popover 里放必填项(用户容易丢失)。

### Toast

- **短**:一句话,3–5 秒消失。
- **位置**:右下或顶部,不挡操作。
- **可撤销**:重要操作的 Toast 必须带"撤销"按钮。
- **慎用**:不要用 Toast 显示重要错误(用户来不及看)。

## 容器的反模式(AI 最常犯)

### 反模式 1:什么都用模态

```
坏的: 删除确认用模态、编辑用模态、查看详情用模态、设置用模态。
病根: 模态是最强的容器,滥用会让用户一直在"被关起来"的感觉里。
```

### 反模式 2:整页跳转打断主任务

```
坏的: 用户在处理任务列表,每点一个任务就跳整页,返回后位置丢了。
病根: 该用抽屉的用了整页。
```

### 反模式 3:抽屉里塞长流程

```
坏的: 抽屉里放一个 8 步表单,用户做得很憋屈。
病根: 该用整页的用了抽屉。
```

### 反模式 4:Popover 放必填项

```
坏的: Popover 里让用户填必填项,用户点外面就丢失。
病根: Popover 是临时容器,不该承担必填决策。
```

### 反模式 5:Toast 显示重要错误

```
坏的: 用户支付失败,只在 Toast 里说一句,3 秒消失。
病根: 重要错误要用 Banner 或 Inline,不能用 Toast。
```

## 容器选型提示词

```
你是一位资深交互设计师。请为下面操作选择最合适的容器,
不要默认"什么都用模态"或"什么都整页跳转"。

操作描述:{用户要做什么}
操作上下文:{用户从哪来、做完去哪}
操作复杂度:{轻量、中等、复杂}
是否需要强制专注:{是/否}
是否需要保留上下文:{是/否}
是否需要可分享 URL:{是/否}

请输出:
1. 推荐容器(整页/抽屉/模态/Popover/Toast)
2. 选择理由(对照决策树)
3. 容器规格(宽度、关闭方式、遮罩)
4. 失败模式提醒(这种选择最容易犯什么错)
```
