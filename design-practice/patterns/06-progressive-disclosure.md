# patterns/06 — 渐进披露(从繁回到简的桥)

> 出处:《设计的实践》第 5 章(行 4557-4565)+ 第 5 编(行 1142-1151)
> 严重度:★★ — 跳过它,产物会"一上来把一桌菜扣用户脸上"
>
> **为什么单独冻结**:这是把"复杂"变回"真简"的核心方法。前面 [判断卡 2 真简 vs 空简](../design-judgment/03-true-vs-empty-simple.md) 讲了"为什么",这一张讲"怎么做"。

## 一句话

> **人的脑子一次装不下太多东西。把二十个选项同时摆出来,用户不是更自由,而是更累。好设计不是把所有选择都公开,而是先给当下最需要的,等用户需要更多时,再把更多给他。**
>
> 大白话:**别一上来把一桌菜扣用户脸上,要一道一道上。**

## 渐进披露的本质

```
新手做法(铺开)         渐进披露做法(分层)
─────────────────       ─────────────────
[20 个选项全摆]          [3 个默认选项]
                        [折叠:"高级筛选"]
                        [展开后露出其他 17 个]
                        
用户第一眼:懵            用户第一眼:清楚
用户操作:犹豫            用户操作:直接动手
```

## 4 个典型应用场景

### 场景 1:筛选器

**差设计**:一个用户列表上方摆满搜索、部门、角色、状态、日期、标签、权限、来源、排序、导出、批量操作——像一堵筛选墙。

**好设计**:默认只给搜索、状态、角色;更多筛选放进抽屉;当前筛选条件用标签显示;一键清空;高级用户能展开,新用户不会被吓退。

### 场景 2:设置页

**差设计**:所有设置项从上到下铺一长页。

**好设计**:基本设置在前(账户、通知、外观);高级设置折叠(快捷键、API、开发者选项);危险设置单独区(删除账户、导出数据)。

### 场景 3:创建流程

**差设计**:一屏 20 个字段。

**好设计**:拆成 3 步(基本信息 → 详细信息 → 确认),每步 5–7 个字段,可保存草稿(见 [patterns/02-complex-flow](./02-complex-flow.md))。

### 场景 4:列表行操作

**差设计**:每一行摆 8 个按钮(编辑/删除/复制/转移/重置/查看日志/导出/更多)。

**好设计**:行内只放最常用的 2 个(编辑/更多);hover 时露出第 3 个;"更多"展开剩下 5 个。

## 渐进披露的 5 个原则

### 原则 1:默认只露主路径 80% 用户需要的

不要默认全部展开,也不要默认全部折叠。**默认应该露出"80% 用户 80% 时候会用到的"**。

### 原则 2:折叠入口要可见,不能藏

"高级"或"更多"按钮要清楚可见,不能藏到角落。藏了 = 用户找不到 = 等于没这功能。

### 原则 3:展开/折叠要可逆,状态要保留

用户展开高级筛选 → 应用 → 关闭 → 再打开,**之前的筛选状态要保留**。展开折叠不是页面刷新。

### 原则 4:不要用渐进披露藏关键操作

撤销、删除、付费、退出登录这类关键操作**不能**折叠到"高级"里。渐进披露是用来藏"低频但必要",不是藏"重要但不想让你点"。

### 原则 5:渐进披露 ≠ 隐藏复杂度

渐进披露是**把复杂度安排到正确层次**,不是把复杂度假装没了。后面那层(高级筛选、高级设置)的功能必须真实可用,不是装饰。

## 渐进披露 vs 复杂度守恒(关键区分)

| 概念 | 解决什么 | 例子 |
|---|---|---|
| **复杂度守恒**(判断卡 1) | 复杂度**归谁**承担 | 默认值替用户先选 = 系统承担 |
| **渐进披露**(本模式) | 复杂度**显示在哪**一层 | 高级筛选折叠 = 用户需要时才显示 |

**两个配合**:复杂度守恒决定"该谁担",渐进披露决定"该谁看见"。比如导出报表:
- 复杂度守恒:格式默认 Excel(系统担),不甩给用户选
- 渐进披露:字段选择放"高级"折叠(用户需要时打开)

## 反模式

### 反模式 1:全部铺开(新手)

```
坏的: 一屏 20 个筛选 + 20 个表格字段 + 8 个按钮
病根: 不懂渐进披露,以为"全露出 = 灵活"。
```

### 反模式 2:全部折叠(过度)

```
坏的: 默认一个输入框,其他全藏在三级菜单里
病根: 反向走极端,用户找不到任何东西。
```

### 反模式 3:藏关键操作

```
坏的: "删除账户"藏在 设置 > 高级 > 账户管理 > 危险操作 > 删除
病根: 用渐进披露藏重要功能。
```

### 反模式 4:折叠状态丢失

```
坏的: 用户展开高级筛选 → 应用 → 切到别处回来 → 高级筛选被折叠,选的也没了
病根: 折叠状态没保留。
```

### 反模式 5:折叠入口看不见

```
坏的: "高级筛选"按钮是个小图标,放在筛选栏右下角,用户根本注意不到
病根: 入口藏太深。
```

## 渐进披露提示词

```text
你是一位资深产品设计师。请为下面页面设计渐进披露方案,
不要把所有选项铺在一屏上,也不要把所有东西藏起来。

页面:{...}
用户主任务:{...}
所有候选项:{列出 15-30 项}

请输出:
1. 默认层(80% 用户 80% 时候需要的,3-7 项)
2. 展开层(高级 / 更多,放剩下的)
3. 折叠入口(放在哪、长什么样、是否明显)
4. 状态保留策略(展开/折叠的状态如何保留)
5. 不能折叠的关键操作清单(必须常驻可见)
6. 反模式自查:
   - 是不是全部铺开?
   - 是不是全部折叠?
   - 有没有藏关键操作?
   - 折叠状态会不会丢?
   - 折叠入口够不够明显?
```
