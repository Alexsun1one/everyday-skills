## 模式层 vs 组件层 vs 判断层(关键区分)

```
判断层 (design-judgment/)
   ↓ 解决:这一仗是什么、复杂度归谁、什么算真简、视觉层级在哪
   ↓
模式层 (patterns/)        ← 你在这里
   ↓ 解决:这个任务用哪种主干道(列表-详情/复杂流程/...)
   ↓      用哪种容器、反馈怎么设计
   ↓
组件层 (components/)
   ↓ 解决:按钮长什么样、输入框有几个状态、表格行如何
```

**判断层 → 模式层 → 组件层**:这个顺序不能跳。

## 模式层使用纪律

1. **先选模式,再画 wireframe**:Stage 1 第一步是判定主模式(是列表-详情?是复杂流程?是单一页面?)。
2. **填模式卡,再画组件**:每个模式文件末尾都有"模式卡",必须填完才能进 wireframe。
3. **反模式自查必跑**:每个模式文件都有反模式清单,Stage 2 完成后必跑。
4. **模式不可混用**:不要在同一个页面里既想要列表-详情的连续处理,又想要复杂流程的强制顺序——会乱。
