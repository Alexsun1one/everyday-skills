# 判断卡 4 — App 是任务网络,不是页面集合

> 出处:《设计的实践》第 13 章(行 6086–6226,原文 33 次提及"任务网络")
> 严重度:★★★ — 跳过它,App 类产物会变成"页面超市",每个页面都好看但用户走不通
>
> **适用范围**:这一卡只在**做 App / 多页面系统**时必填。单页(landing / 工具页)可跳过。

## 一句话

> **不要先列页面,要先列任务。用户不是来"访问页面"的,用户是来完成任务的。设计 App 的第一步,不是画页面地图,是画任务地图。**

## 新手 vs 高手做 App

### 新手的做法(画布思维)

打开白板列页面:
- 登录页、首页、列表页、详情页、设置页、个人中心、通知页、帮助页...

**为什么这条路一开始就走偏**:用户心里想的不是"我要去详情页",而是"我要看这个订单有没有发货";不是"我要打开设置页",而是"我要把通知关掉"。

### 高手的做法(任务网络思维)

第一步先列任务:
```
用户最常来这里办哪三件事?
用户每次来必办的哪一件事?
哪些任务是连续的(做完 A 接着做 B)?
哪些任务是低频但重要(每月/每季/每年)?
哪些任务是被打扰触发的(来通知→来 App→处理)?
```

然后**让任务决定页面**,而不是页面决定任务。

## 任务地图的画法

### Step 1:列核心任务(不超过 5 条)

每个任务用"角色 + 动词 + 对象 + 目的"的格式:

```
例:任务管理 App
- [PM] 创建 [任务] 为了 [把需求拆解]
- [成员] 查看 [今天要做的] 为了 [知道先做什么]
- [PM] 跟进 [进行中任务] 为了 [发现阻塞]
- [成员] 更新 [任务状态] 为了 [让 PM 知道进度]
- [所有人] 通知 [相关人] 为了 [协同]
```

### Step 2:把任务连成网络(不是页面树)

任务之间有四种关系:

| 关系 | 意思 | 例子 |
|---|---|---|
| **连续** | 做完 A 接着做 B | 创建任务 → 分配负责人 |
| **触发** | 事件 X 触发任务 Y | 收到评论 → 回去看任务 |
| **回退** | 做完 A 回到 B | 改完状态 → 回到列表 |
| **并行** | A 和 B 同时存在 | 看任务 + 看通知 |

画出来是**网状**,不是树状:

```
创建任务 ──连续──> 分配负责人
                       │
                       ▼ 触发
                  通知负责人
                       │
                       ▼
                  查看任务 <──回退── 更新状态
                       │
                       ▼
                  添加评论 ──触发──> 通知 PM
```

### Step 3:页面只是任务的"驿站"

任务网络画完后,**页面是任务经过的驿站,不是任务的目的地**:

| 页面 | 它服务于哪些任务 | 必须有什么 |
|---|---|---|
| 任务列表 | "知道今天先做什么"、"跟进进行中" | 优先级、阻塞、归属 |
| 任务详情 | "查看具体任务"、"更新状态" | 状态、属性、历史、操作 |
| 通知中心 | "处理被打扰的事" | 来源、跳转、已读未读 |
| 个人设置 | "改我的偏好" | 低频但必有的开关 |

**关键**:页面不是孤岛。每个页面都要回答"用户从哪来 / 在这干什么 / 干完去哪"。

## 任务网络的反模式(AI 产物最常犯)

### 反模式 1:页面超市

```
坏的 App: 登录 / 首页 / 列表 / 详情 / 设置 / 个人中心 / 通知 / 帮助 / 关于
         每页都漂亮,但用户走不通。
病根: 先列页面,没列任务。
```

### 反模式 2:断头任务

```
坏的: 用户在详情页改了状态,但没有反馈、没有"下一步"、没有回到列表。
病根: 任务没有"出口"。
```

### 反模式 3:重复入口

```
坏的: 同一个任务在 3 个页面都有入口,用户不知道该用哪个。
病根: 任务没有"主路径",所有页面都抢着做同一件事。
```

### 反模式 4:孤立页面

```
坏的: 设置页跟主任务流断开,用户得绕 5 步才能到。
病根: 任务网络没画,页面是堆出来的。
```

## 任务网络 → 页面清单 的转换规则

| 任务特征 | 页面形态 |
|---|---|
| 高频 + 多对象 + 需要扫视 | 列表页(见 patterns/01-list-detail) |
| 高频 + 单对象 + 需要处理 | 详情页 / 抽屉 |
| 低频 + 配置类 | 设置页(深处) |
| 触发型 + 短任务 | 通知中心 / Banner 跳转 |
| 多步骤 + 不能中断 | 向导(见 patterns/02-complex-flow) |

## 任务网络提示词(原文 13 章提供)

```
你是一位资深产品设计师。请基于下面信息,先画任务网络,再列页面,
不要先列页面。

产品定位:{一句话}
目标用户:{角色 + 场景}
用户的 3 个主任务:{动词 + 对象 + 目的}

请输出:
1. 任务清单(不超过 5 条,每条"角色+动词+对象+目的")
2. 任务网络(连续/触发/回退/并行关系)
3. 每个任务经过的"驿站"(页面)
4. 页面之间的跳转关系
5. 任务出口(每个任务做完用户去哪)
6. 哪些任务是低频但必要,如何安放(深处设置/通知触发)

要求:
- 不要先列页面
- 不要让任务"断头"(没有出口)
- 不要让一个任务有多个并列入口
```

## 判断卡(复制到 Stage 0 输出,做 App 时必填)

```

□ 每个任务的出口(用户做完去哪):
□ 低频但必要任务清单 + 安放策略:

```

**做 App 不填这张卡,后面所有页面都是孤岛。**
