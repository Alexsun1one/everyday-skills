# 判断卡 1 — 复杂度守恒

> 出处:《设计的实践》第 4 章(行 4166–4445,原文 6 次提及"复杂度守恒")
> 严重度:★★★ — 跳过它,产物要么"假简单"(功能少得像 demo),要么"假灵活"(把系统该处理的复杂全甩给用户)

## 一句话

> **复杂度不会消失,只会转移。好设计不是把复杂度变没,而是把它安排到正确位置:该用户承担的,让用户清楚承担;该系统承担的,让系统默默承担;该团队流程承担的,不要甩给界面;该 AI 承担的,要给它足够清楚的规则。**

## 复杂度分配的四个去向

```
真实世界复杂度
       │
       ▼
   由谁承担?
   ┌─────────────────┬─────────────────┬─────────────────┬─────────────────┐
   ▼                 ▼                 ▼                 ▼
用户承担           系统承担           团队承担           AI 承担
选择、确认、判断    默认值、校验、     流程、规则、运营    生成、整理、评审
                   自动化
   │                 │                 │                 │
   ▼                 ▼                 ▼                 ▼
界面必须解释清楚   界面必须反馈清楚   界面不能替流程背锅  提示词必须约束清楚
```

## 四类典型"复杂度甩锅"病(产物 AI 味的主要来源)

| 病名 | 症状 | 例子 | 病根 |
|---|---|---|---|
| **甩给用户** | 选项 20 个,无默认值,无解释 | 导出页让用户选字段/格式/编码/日期格式/压缩/邮件 | 设计偷懒,逃避决策 |
| **甩给界面** | 团队没想清的规则,全堆到 UI 上 | "审核规则"用 5 个开关表示,实际是业务流程没定 | 业务没定,设计背锅 |
| **甩给系统假装** | 系统该自动化的,做成手动 | 用户每次都要选时间区、选语言、选币种 | 该写默认值的没写 |
| **AI 无规则** | AI 在没有约束下生成 | "让 AI 生成报表" 但没说生成给谁、什么口径、什么动作 | 提示词太松 |

## 守恒判断三步法

### 第 1 步:列出这一仗的全部复杂度

不要漏。把用户在使用这一页时,**脑子里冒出的所有疑问**写出来:

```
例:CRM 客户详情页
- 这个客户现在什么阶段?
- 上次联系是什么时候?
- 谁负责?
- 有没有未处理的工单?
- 有没有回款风险?
- 历史合同有哪些?
- 我能不能改这个客户?
- 改完谁会知道?
- 如果我改错了能撤销吗?
- 这个客户归哪个团队?
...
```

### 第 2 步:每一条复杂度,判定归谁

| 复杂度条目 | 归用户(选择) | 归系统(默认/校验) | 归团队(规则) | 归 AI(整理/生成) |
|---|---|---|---|---|
| 客户阶段 | ☐ 改阶段 | ☐ 阶段流转规则 | ☑ 阶段定义归业务 | ☐ |
| 上次联系 | ☐ | ☑ 自动记录 | ☐ | ☐ |
| 风险 | ☐ | ☑ 风险规则 | ☑ 风险阈值归运营 | ☐ |
| 处理工单 | ☑ 决定怎么处理 | ☐ | ☐ | ☑ 总结工单 |
| 改完通知谁 | ☐ | ☑ 通知规则 | ☑ 通知对象归配置 | ☐ |
| 撤销 | ☑ 决定撤销 | ☑ 撤销窗口/范围 | ☐ | ☐ |

### 第 3 步:界面只显示"该用户承担的"+ 系统反馈

归用户的 → 进 UI(清楚解释后果)。
归系统的 → 进 UI 反馈(发生时告诉用户)。
归团队的 → 不进 UI,或者只在"违反规则"时给一句解释。
归 AI 的 → 给 AI 明确规则(prompt 约束),不让它在 UI 里"自由发挥"。

## 守恒反例(产物 AI 味的直接证据)

**反例 A:假简单(复杂度被隐藏了,但没被处理)**

```
坏的: 订单列表只显示订单号和金额。
为什么坏: 用户真实的复杂度(付款了吗?发货了吗?退款吗?)被吞了,
         不是被处理了。用户进详情页才发现要自己查。
守恒判断: 复杂度被"假装没了",其实甩给了用户多一次跳转。
```

**反例 B:假灵活(复杂度全甩给用户)**

```
坏的: 报表页给用户 30 个字段可选、5 种图表可选、3 种时间维度可选,
     无默认值。
为什么坏: 这是设计逃避责任。系统明明知道"多数销售只想看本月成交"。
守恒判断: 该归系统(默认值)的复杂度,被甩给了用户。
```

**反例 C:AI 无规则生成**

```
坏的: 客户详情页底部加"AI 总结",但没说总结给谁、给多长、错了怎么办。
为什么坏: AI 承担的复杂度没有规则约束,会出乱七八糟的输出。
守恒判断: 该归 AI 的复杂度,提示词太松。
```

## 判断卡(复制到 Stage 0 输出)

```
【判断卡 1 — 复杂度守恒】
□ 这一仗用户脑子里会冒出的全部疑问(列 5–15 条):
□ 每条疑问归谁承担(用户/系统/团队/AI):
□ 这一页的"假简单"风险(哪些复杂度被吞了):
□ 这一页的"假灵活"风险(哪些复杂度被甩给用户):
□ 默认值清单(系统该替用户先定什么):
□ 高级选项折叠策略(哪些放进"高级"):
□ AI 介入点的提示词约束(如果用了 AI,规则写清):
```

填不出第 1、2 行 → 你没看清这一仗。
填不出第 5 行 → 你在偷懒,把决策甩给用户。
