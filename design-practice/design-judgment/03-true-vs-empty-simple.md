# 判断卡 2 — 真简 vs 空简

> 出处:《设计的实践》第 5 章(行 4446–4731)
> 严重度:★★ — 跳过它,产物要么"假干净"(空简),要么"过度设计"(假复杂的简)

## 一句话

> **简单有两种:一种是新手没想全,所以看起来空;另一种是高手把复杂问题都想透、安排好,最后呈现给用户一个清楚的主路径。前者叫"空简",后者叫"真简"。**

## 三段进化曲线

```
新手          专业          大师
(空简)  →   (复杂)   →   (真简)
  ↑                            ↑
  └── 看起来都"简",但内核完全相反 ──┘

新手简 = 没想全,所以空
大师简 = 想全了,所以只露主路径,把其他复杂度安排到该去的位置
```

## 三种简的判别

| 维度 | 空简(新手) | 过度复杂(新手假装专业) | 真简(大师) |
|---|---|---|---|
| 信息量 | 少得可怜 | 多得拥挤 | 主路径少,其他都藏好 |
| 状态 | 只有默认态 | 多但乱 | 默认 + 异常 + 边界全覆盖 |
| 用户路径 | 一条,断了 | 多条,乱 | 一条主路径 + 必要分支 |
| 异常处理 | 没有 | 弹窗满屏 | 默默处理,只在需要时露 |
| 看起来 | 干净得像 demo | 复杂得像后台 | 简单得像常识,但有底气 |

## 真简的四个标志

**1. 主路径只有一条,但异常路径全套**

新手做的"邀请成员"= 一个输入框 + 一个按钮。
大师做的"邀请成员"= 主路径(输邮箱→选权限→发邀请),异常(已存在/无邮箱/超权限/批量/撤回/重新发)全都安排好,只是默认折叠。

**2. 看起来空,但底层规则满**

新手做的"导出"= 一个按钮。
大师做的"导出"= 按钮后藏着:默认导出当前视图、Excel 格式、自动命名、邮件通知、保留 7 天、超额提醒。用户只看到一个按钮,系统承担了所有复杂度。

**3. 默认值替用户决策**

新手让用户选时间/格式/语言/币种。
大师替用户先选好(基于上下文),只在边缘留个"修改"入口。

**4. 复杂度被分配到该去的地方**

参见 [判断卡 1 复杂度守恒](02-complexity-conservation.md)。真简的前提是复杂度被正确分配。

## 自检问题(决定你是哪种简)

> **"我的简单,是因为我没想全,还是因为我想全了只露主路径?"**

判别方法:把你的"简"页面对着下面 5 个问题问一遍:

```
□ 我有没有想"用户做错怎么办"?
□ 我有没有想"用户的数据是脏的怎么办"?
□ 我有没有想"用户没权限怎么办"?
□ 我有没有想"用户中间退出再回来怎么办"?
□ 我有没有想"用户做完想撤销怎么办"?
```

全答"没想" → 你的简是**空简**,要回炉。
全答"想了但默认隐藏" → 你的简是**真简**,过关。

## 真简 vs 空简的视觉差别(重要)

很多人误以为"简 = 留白多 = 字号小 = 颜色淡"。错。

| 视觉特征 | 空简(没想全) | 真简(想全了) |
|---|---|---|
| 主行动按钮 | 不清楚 | 极清楚(权重最高) |
| 状态信号 | 没有或单一 | 主路径无,但 hover/详情里有 |
| 错误提示 | 没有 | 就地,具体,可恢复 |
| 空状态 | "暂无数据" | 解释为什么空 + 第一步行动 |
| 加载 | 旋转圈 | 骨架 + 进度 + 上下文保留 |
| 撤销 | 没有 | 明确的撤销窗口 |

**真简看起来简,是因为主路径干净;但仔细看,异常、状态、撤销都备齐了。**
