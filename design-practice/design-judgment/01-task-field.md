# 判断卡 0 — 页面是任务场,不是画布

> 出处:《设计的实践》第 2 章(行 5677–5917,原文 18 次提及"任务场")
> 严重度:★★★ — 跳过它,Stage 1 一切 wireframe 都是从"先画组件"开始,产物立刻 AI 味

## 一句话

> **不要问"这个页面怎么排好看",要问"用户来这里打哪一仗"。页面不是给设计师发挥审美的画布,而是用户完成任务的现场。先看清现场,再谈构图、颜色、组件、动效,否则房子建歪。**

## 为什么这是判断层第 0 张卡

很多人打开 Figma / Cursor / v0,第一句就是"帮我设计一个好看的页面"。这一步**已经晚了**。AI 工具最会糊这种请求——直接套模板,给你一坨卡片堆。专业设计师第一问永远是:

> **用户在这一页要完成的"那一仗"是什么?这一仗发生在什么地形上?**

- 用户:**谁**,什么角色,什么权限,什么熟练度,正在干什么,什么设备,心里急不急。
- 战场(页面):用户要在这页**找什么、判断什么、做什么、确认什么、退出时带走什么**。
- 仗(任务):主任务一条,辅助任务两三条。**一条主任务都说不清,不要画。**

## 三步判别法

### 第 1 步:把"页面名"翻译成"仗名"

新手会说"做一个**项目首页**"。高手会说"做一个**让 PM 一眼看见所有进行中项目里哪个亮红灯、点进去能救火**的页"。前者是画布思维,后者是任务场思维。

判别:
- 描述里有"**首页 / 列表页 / 详情页 / 设置页**" → 画布思维,要重写。
- 描述里有"**让 X 角色 干 Y 事**" → 任务场思维,可以进下一步。

### 第 2 步:把"仗"拆成 5 个动作

任何页面的任务场,都可以拆成 5 个动作里的一条或几条:

| 动作 | 用户的内心 | 页面要给什么 | 例子 |
|---|---|---|---|
| **找** | "我在找一个对象" | 可扫的列表 + 筛选 + 关键信号 | 客户列表、issue 列表、订单列表 |
| **判断** | "我要不要做、先做哪个" | 状态、优先级、风险、归属 | 仪表盘、待办、审批队列 |
| **处理** | "我要改一个东西" | 对象现场 + 可编辑区 + 保存 | 任务详情、订单详情、客户资料 |
| **确认** | "我做完了,系统收到了吗" | 反馈 + 下一步 + 撤销 | 提交后的成功页、保存 Toast |
| **退出** | "我从哪来回哪去" | 返回路径 + 上下文保留 | 返回列表、关闭抽屉 |

**一个页面通常只承担 1–2 个动作**。塞 5 个动作的页面不是"功能全",是"任务场被打散"。

### 第 3 步:画"战场地图"(不画组件,画路径)

任务场思维的核心产物不是 wireframe,是**用户走在这页上的路径图**:

```
[进入点] → 第一眼看到 X → 扫一眼 Y → 点击 Z → 处理 → 反馈 → [出口]
```

这张路径图决定了:**第一眼应该摆什么、点击后什么变成什么、退出时带走什么**。组件只是路径的载体,不是路径本身。

## 反例(AI 工具最常犯)

```
用户:"帮我做一个 CRM 客户列表页"
坏的 AI: 直接画 [顶栏 + 左侧导航 + 中间卡片网格 + 右侧推荐]
为什么坏: 没问"销售在客户列表这一仗打的是什么"。
         销售要的是"今天该先跟谁联系、谁有风险、谁该升级",
         不是"客户卡片摆得好看"。
好的判断: 任务场=找+判断。
         第一眼信号=最近未联系天数 / 风险标签 / 金额。
         路径=筛风险→点客户→看互动历史→记录新跟进。
```

## 判断卡(复制到 Stage 0 输出)

```
【判断卡 0 — 任务场】
□ 这一仗的主任务(动词开头,一句话):
□ 用户角色与状态(谁、急不急、熟不熟、什么设备):
□ 这一页承担的 5 个动作里的哪 1–2 个(找/判断/处理/确认/退出):
□ 用户路径图:进入点 → 第一眼 → 扫视 → 点击 → 处理 → 反馈 → 出口
□ 这一仗打完,用户带走什么(决策?记录?下一步?)
□ 这一仗打完,系统留下什么(数据更新?日志?通知谁?)
```

填不出第 1 行,回 Intent Brief 重问。
填不出第 4 行,做不了 Stage 1 — 因为没有路径,wireframe 就是组件堆。
